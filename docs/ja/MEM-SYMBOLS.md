# mem のシンボル表示（試験実装）

`mem` は従来のメモリ表示に加え，RAMアプリのELFからビルド時に抽出されたシンボルを参照できます．シンボル情報はファームウェアに同梱され，`/proc/syms`（読み取り専用）から取得します．実行中にELFファイルを開く方式ではありません．

```text
mem -s            # シンボル情報のあるアプリ一覧
mem -s sh         # sh の関数・変数などのシンボル一覧（相対オフセット）
mem -s mb         # mb のシンボル一覧
mem 0x20018000    # 指定アドレスから通常のメモリ表示
mem 0x20018000 sh # 指定アドレスを表示し，ASCII欄の右にshのシンボル名を表示
```

`mem -s kernel` は現段階では非対応です．カーネル自身の最終リンク後のシンボルをファームウェア内部に埋め込むには，別の生成手順が必要です．

## 注意点

- `sh` はアプリ名（`/bin` の名前）です．`shell` ではありません．
- 一覧のアドレスは，リンク時の基準アドレス `0x20018000` からの相対オフセットです．実行時のスロット配置はシンボルだけからは確定できません．
- `mem アドレス アプリ名` の右欄は**指定したアプリがその32KiBスロットに配置されていると仮定**したラベルです．現在のプロセス表から自動的に対応関係を確定していません．ほかのアプリが配置されているスロットに誤ったアプリ名を指定すると，ラベルも誤ります．
- ラベルは対象行にシンボル開始アドレスが含まれるときだけ表示します．データ型や変数の値は解析しません．
- `mem -s` でシンボル情報を取得できない場合は，メッセージを表示して終了します．通常の `mem [アドレス]` の動作は維持します．
- `mem アドレス アプリ名` でシンボル情報がない場合も，全画面モードに移行せずメッセージを表示して終了します．
- アドレスは `/dev/mem` が認めるSRAM・XIP Flashの範囲に限定します．
- 出力の追加列は広い端末を想定しています．端末の桁数が小さい場合，右側が表示されないことがあります．

## ビルド

`tools/make_symbols.py` が各アプリのELFから `T/t/D/d/B/b/R/r` のシンボルを抽出し，ソートしたテキスト形式のカタログを生成します．`.incbin` によってファームウェアへ埋め込みます．ビルド時にELFの解析に失敗したアプリはスキップします．

ZIPを展開した後に変更が反映されない場合は，更新日時を確認してください．
