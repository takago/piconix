## 2026-11-07：基本ポインタ機能（新）

`cc`は`int *`と`char *`（1段階のポインタ）の局所変数・関数引数，`&x`，`&a[i]`，`*p`，`*p = 値`，`p[i]`，`p + n`，`p - n`に対応しました．配列名をポインタとして引数へ渡せます．`int *`の加減算は4バイト単位，`char *`は1バイト単位です．`read()`と`write()`にはポインタ式を渡せます．

```c
void swap(int *a, int *b)
{
    int temp;
    temp = *a;
    *a = *b;
    *b = temp;
}

int main(void)
{
    int x;
    int y;
    x = 10;
    y = 20;
    swap(&x, &y);
    if (x == 20) {
        if (y == 10) { write(1, "PASS\n", 5); }
    }
    return 0;
}
```

```sh
cc test.c
as test.s
/tmp/a.out
```

**現段階の制限**：`int **`などの多重ポインタ，ポインタの配列，構造体，ポインタ同士の減算，ポインタを戻り値とする関数，`++`，`--`，`malloc()`，関数ポインタには未対応です．ポインタ演算の境界検査はなく，不正アドレスへのアクセスは危険です．256バイトの関数スタック領域，Cソース最大1024バイト，アセンブラ入力最大2048バイトの制限があります．ホスト側では生成・アセンブルを検証しましたが，実機実行は未検証です．

## 2026-11-07：局所変数のアドレスと大きな整数定数

`char c;`，`int n;`のような単一の局所変数に対して，`&c`や`&n`でアドレスを取得できます．`read()`と`write()`では，配列名または`&`を付けた単一の局所変数をバッファ引数に指定できます．要素数1の配列（`char c[1];`）も配列として扱います．

```c
int main(void)
{
    char c;
    int n;
    n = read(0, &c, 1);
    if (n == 1) {
        write(1, &c, 1);
    }
    return 0;
}
```

0〜2147483647の10進整数定数にも対応しました．`movs`で直接設定できない値は，Thumb-1の`adds`を組み合わせて32ビット値を組み立てます．負数は単項`-`で表現します．

```c
void print_number(int n)
{
    char digit[1];
    if (n >= 10) {
        print_number(n / 10);
    }
    digit[0] = '0' + n % 10;
    write(1, digit, 1);
}

int main(void)
{
    print_number(12345);
    write(1, "\n", 1);
    return 0;
}
```

`cc`の出力先は入力の拡張子を`.s`に変えた同じディレクトリのファイル，`as`の出力先は`/tmp/a.out`です．一般的なポインタ変数，ポインタ演算，配列引数を持つ関数は未対応です．配列の添字境界検査は行いません．大きな定数は命令列が長くなるため，`cc`の4096バイト出力制限と`as`の2048バイト入力制限に注意してください．`/tmp/a.out`の実機実行は本修正では未検証です．

> **現行実装と検証（2026-11-07）**：ローカル領域は256バイト固定で，`int`・`char`・配列・`sizeof`・`read(fd,buf,n)`・`write(fd,buf,n)`の一部に対応します．下の古い節には64バイトなど過去の段階の記述が残っています．最新仕様は本節とソースコードを優先してください．テストは `python3 tools/test_scripts/test_cc_regressions.py` と既存の `test_cc_*.py` です．テストはC→Thumb機械語の生成までで，実機実行は未検証です．

# PicoNIX 教育用Cコンパイラ `cc`

`cc` はPicoNIX上で動く最小限のCサブセットコンパイラです．Cソースを既存の`as`が解釈できるThumb-1アセンブリに変換します．汎用Cコンパイラではありません．

## 最初の実習

`cat > /tmp/hello.c`で以下を入力し，Ctrl+Dで保存します．

```c
int main(void) {
    write(1, "Hello, PicoNIX!\n", 16);
    return 0;
}
```

```sh
cc /tmp/hello.c
cat /tmp/hello.s
as /tmp/hello.s
./a.out
```

`cc`は入力ファイルと同じディレクトリに同名の`.s`ファイルを生成します（例：`cc test.c` → `test.s`，`cc /tmp/hello.c` → `/tmp/hello.s`）．`as`の出力先は従来どおり`/tmp/a.out`です．`cat`で中間生成物を観察してください．

## 対応範囲

- `int main(void)`または`int main()`の一つの関数
- `write(fd, "文字列", count);`（標準の3引数形式．fdは0〜2，countは0以上で文字列の実際のバイト数以下）
- `getpid();`（戻り値は利用しない）
- `int i = 0;`，`i = i + 1;`などの整数変数と代入（最大16個，スタック上の64バイトに配置）
- `if (i == 3) { ... } else { ... }`，`while (i < 3) { ... }`（ブロック必須）
- 条件比較は `==`，`!=`，`<`，`<=`，`>`，`>=` と0〜255の整数定数（符号付き32ビット比較）
- 式は整数定数または変数，および定数を加減算する単純な式
- `return N;`（0〜255）
- `//`および`/* ... */`コメント，複数の文

**未対応**：一般的な演算式，乗除算，負数，配列，ポインタ，複数の関数，変数やポインタを渡す一般的な`write(fd,ptr,len)`，`#include`．サポート外の構文はエラーにします．

`count`は明示指定します．文字列リテラルの長さを超える指定は，領域外読み取りを防ぐためコンパイルエラーです．`write(1, "HELLO", 3);`なら先頭の`HEL`だけを出力します．現段階では数値定数のみ指定できます．

## 内部の仕組み

1. `cc` が空白とコメントを読み飛ばし，文法を認識します．
2. `write`を`movs`，`adr`，`svc #0`へ変換します．`r0=9`はwriteのシステムコール番号，`r1`はFD，`r2`は文字列アドレス，`r3`は長さです．
3. 文字列は分岐命令の後ろに配置し，`.align 2`で整列します．`adr`によって位置独立で参照できます．
4. `return N`は`r0=3`のexitシステムコールに変換します．関数末尾にも`exit(0)`を置きます．
5. `as`がPNX1形式の機械語を生成し，シェルが実行します．

`svc #0`の0はシステムコール番号ではありません．番号は`r0`に渡します．

## 制限と注意

ソースは最大1024バイト，出力アセンブリは最大2048バイト，`as`の出力機械語は2040バイト以下です．`as`のラベル数上限は32です．文字列は英数字・ASCII記号・`\n`・`\r`・`\t`・`\\`に限定し，ダブルクォートのエスケープは扱いません．`cc`は不正なソースをすべて診断できるわけではありません．生成したバイナリはメモリ保護なしで実行されるため，信頼できるソースのみ実行してください．

## 発展課題

現在は16個の変数をスタック上に固定割当し，`if`と`while`を条件分岐ラベルで実現します．符号なし8ビット範囲の定数だけを扱い，整数演算のオーバーフローやレジスタ保存規約を一般的なCコンパイラのようには保証しません．次の課題は式の一般化，`else`と関数呼び出しです．

## 変数とループの実習

```c
int main(void) {
    int i = 0;
    while (i < 3) {
        write(1, "HI\n", 3);
        i = i + 1;
    }
    if (i == 3) { write(1, "OK\n", 3); }
    return 0;
}
```

`cc /tmp/loop.c`，`cat /tmp/loop.s`，`as /tmp/loop.s`，`./a.out`の順に実行し，`cmp`，`bcs`，`bne`，`b`の対応を観察してください．

関連：[アセンブラ](../asm/ASM.md) ｜ [システムコール](../../../reference/SYSCALLS.md)

## 条件分岐の実習

```c
int main(void) {
    int i = 0;
    while (i < 5) {
        if (i <= 2) { write(1, "LOW\n", 4); }
        else { write(1, "HIGH\n", 5); }
        i = i + 1;
    }
    return 0;
}
```

`>`と`<=`は既存の`bcc`，`beq`，`b`を組み合わせて実現します．比較は `blt`，`ble`，`bgt`，`bge` を用いた符号付き比較に変更しました．


## スタック変数の実装（2026-11-07）

`cc`は関数開始時に`sub sp, #64`で16個分の32ビット整数領域を予約します．各変数は宣言順に`[sp, #0]`，`[sp, #4]`のように割り当てられ，`ldr`と`str`で読み書きします．`as`には`sub sp, #N`，`add sp, #N`（4の倍数，最大508）と`ldr/str rN, [sp, #offset]`（4の倍数，最大1020）を追加しました．既存のレジスタ相対メモリ命令も利用できます．

このコンパイラは教育用の限定的なCサブセットであり，スコープ，関数呼び出し，任意の式，符号付き比較，スタックフレームの動的管理には未対応です．`return`はPicoNIXの`exit`システムコールへ変換するため，通常のC関数の復帰処理とは異なります．

## 再帰下降パーサと整数式（2026-11-07）

式解析は `expression → additive → multiply → unary → primary` のトップダウン構造です．`primary` は整数定数，変数，括弧式を処理し，`unary` は単項 `+` と `-`，`multiply` は `*`，`/`，`%`，`additive` は `+`，`-` を処理します．`if` と `while` の比較の左右にも式を書けます．

```c
int main(void) {
    int a = 10;
    int b = 3;
    int c;
    c = (a + b * 2) / 4;
    if (c == 4) { write(1, "OK\n", 3); }
    return 0;
}
```

`cc /tmp/example.c` → `as /tmp/example.s` → `./a.out` の順で試します．式の中間値は `push {r0}` と `pop {r1}` で保存します．乗算はThumbの `muls` を利用し，除算と剰余は減算を繰り返す教材向けの簡易実装です．

**制限**：除算・剰余は非負整数向けで，負数の標準C意味論は未実装です．ゼロ除算はエラーを通知せずゼロを返すため，標準C互換ではありません．比較は符号付き32ビットです．32ビット整数のオーバーフロー，式の深い入れ子，アセンブラの分岐距離と出力サイズに制限があります．実機実行は未検証です．ホスト検査は `python3 tools/test_scripts/test_cc_expressions.py` で実行します．

## `char` と配列（試験実装）

`int` は32ビット，`char` は1バイトです．ローカル配列はスタック上に確保します．最大16個のローカル変数宣言，合計256バイトの固定スタックフレームを使用します．配列の要素は `a[i]` で読み書きでき，`sizeof(a)` は配列全体のバイト数です．文字定数と `char msg[6] = "HELLO";` の初期化に対応します．

```c
int main(void) {
    char buf[8];
    int n = read(0, buf, 8);
    if (n > 0) {
        write(1, buf, 8);
    }
    return 0;
}
```

**制約**：`read` / `write` の配列バッファに対する第3引数は整数式を指定できます．添字の範囲検査はありません．負の添字や範囲外の添字を使わないでください．`char` の符号付き／符号なしの区別，ポインタ宣言，一般的な関数呼び出し，スコープ管理は未対応です．標準C完全互換ではありません．実機での実行確認も未実施です．

生成コードは `addsp`（SP相対アドレス取得），`ldrb` / `strb`（バイトアクセス），`ldr` / `str`（ワードアクセス）を使用します．`as` に `addsp` を追加しています．テストは `python3 tools/test_scripts/test_cc_char_arrays.py` で実行します．

## システムコールの可変引数（2026-11-07）

```c
int main(void)
{
    char buf[32];
    int n = read(0, buf, sizeof(buf));
    if (n > 0) {
        write(1, buf, n);
    }
    return 0;
}
```

`read(fd, 配列, バイト数)` と `write(fd, 配列, バイト数)` は，FDとバイト数に整数式を使用できます．バッファはローカル配列の名前に限定されます．引数は左から評価し，途中結果をスタックに保存した後，`r1=fd`，`r2=アドレス`，`r3=バイト数` を設定し，`r0=システムコール番号` として `svc #0` を発行します．`read` の戻り値は `r0` に残るため，変数への代入ができます．

配列容量を超える実行時の長さは検査しません．`read` で読み込んだバイト数が正の場合だけ `write` に渡してください．テスト：`python3 tools/test_scripts/test_cc_syscall_args.py`．実機実行は未検証です．

### 符号付き比較の検証（2026-11-07）

`cc` は `cmp` の後に符号付き分岐（`blt`，`ble`，`bgt`，`bge`）を生成します．`as` はこれらをThumb-1条件分岐へ変換します．`python3 tools/test_scripts/test_cc_signed_comparisons.py` で生成コードと命令符号を確認できます．この検査はCPU上の実行テストではありません．除算・剰余の負数対応，実機実行検証は引き続き課題です．


## ユーザ定義関数（試験的対応）

`int`型の戻り値を持つ関数，`void`関数，最大4個の`int`型引数，局所変数，関数の入れ子呼び出し，再帰呼び出しのコード生成に対応しました．引数は`r0`〜`r3`，戻り値は`r0`を使用します．各呼び出しで`lr`を保存し，256バイトの局所スタックフレームを確保します．関数の前方参照にも対応しますが，宣言プロトタイプだけを書く構文は未対応です．

```c
int add(int a, int b) {
    return a + b;
}
int main(void) {
    return add(10, 20);
}
```

`cc sample.c` → `as sample.s` → `./a.out` の順に実行します．関数は最大16個で，関数呼び出しは最大32箇所です．引数型は`int`のみで，配列やポインタを引数に渡す機能は未対応です．入れ子の呼び出しではスタックの8バイト整列を完全には保証していないため，AAPCS完全準拠ではありません．再帰はアセンブルを確認していますが，実行結果は未検証です．

`tools/test_scripts/test_cc_functions.py`は関数定義，複数引数，入れ子呼び出し，再帰のコード生成とアセンブルを検査します．実機検証は別途必要です．

## 生成アセンブリのインデント

`cc`が生成する`.s`ファイルでは，命令行に半角スペース2個のインデントを付けます．ラベルと`.align`・`.ascii`などのアセンブラ指示は行頭に配置します．`as`は行頭の空白を読み飛ばすため，この変更は機械語の内容に影響しません．ただし，空白の増加により，長いプログラムではアセンブリソース長の上限に達しやすくなります．

```asm
f_add:
  push {r4, lr}
  sub sp, #256
  ldr r0, [sp, #0]
  add sp, #256
  pop {r4, pc}
```

### 関数呼び出し時の局所変数参照（2026-11-07）

局所変数と引数は`r4`をフレームポインタとして参照します．式の途中で`push`しても参照先がずれないため，`calculate(3,4)`内で`add(a,b)`を呼び，その結果を`square(sum)`へ渡す処理が正しくコード生成されます．`r4`は関数の入口で保存し，終了時に復元します．実機での動作は別途確認が必要です．
