## 1．新しいシステムコールを追加する

### 1.1 番号とABIを決める

`include/piconix_syscall.h`の`PICONIX_SYSCALL_TABLE(X)`に，現在1〜39番が定義されています．**11番と15番は予約済み**です．既存番号を並べ替えたり流用したりしないでください．新しい番号は末尾に明示的に追加するのが安全です．ユーザ側`userland/lib/syscalls.c`は共通ヘッダの`SYS_*`定数を用いており，カーネル側と番号を共有します．新設する際も，この表を唯一の番号定義として使用してください．

呼び出し規約は，`r0`＝番号，`r1`〜`r3`＝引数，`svc #0`，復帰時`r0`＝結果です．4引数以上の情報には構造体ポインタを用いるなどして設計してください．エラーは通常，負の`OS_E*`値で返し，`errno`に依存しません．[SYSCALLS.md](../../reference/SYSCALLS.md)を参照してください．

### 1.2 カーネルの処理を追加

`kernel/kernel.c`の`os_svc_dispatch(uint32_t *f)`には，番号の分岐と結果を設定する`switch(num)`があります．既存の簡単な`SYS_FLASH_ID`や`SYS_GETPID`の処理を例に，追加するケースで`result`を設定します．

```c
/* 追加位置を示す模式例．未定義番号や関数をそのまま貼り付けないこと． */
case SYS_EXAMPLE:
    result = example_kernel_operation(a);
    break;
```

`a`，`b`，`c`は`r1`〜`r3`から取得されます．ユーザポインタを参照するときは，既存の`in_task_range()`や文字列パス検証の実装を参考に，**長さ，範囲，終端，整数オーバーフローを参照前に検査**してください．ポインタを単純にキャストして任意アドレスを参照しないでください．タスク状態を変える操作，割込みと共有する状態，待機処理は既存の同期・スケジューラ規約を確認してください．

### 1.3 ユーザ側APIを公開

`userland/lib/syscalls.c`の`call(n, a, b, c)`は`svc #0`を発行します．新しいC関数のラッパーを追加し，`userland/lib/unistd.h`など適切な公開ヘッダに**対応するプロトタイプ**を追加してください．名前，型，エラー時の値がカーネルと一致することを確認します．変更後は[LIBC.md](../apps/c/LIBC.md)と[SYSCALLS.md](../../reference/SYSCALLS.md)の日英両方を更新します．

### 1.4 テストで確認

- 既存番号・予約番号が不変であること，新番号が重複しないこと
- 引数0・上限値・不正FD・不正ポインタ・巨大サイズで適切なエラーを返すこと
- 失敗してもタスク状態・FD・バッファを破損しないこと
- Cラッパーの番号と引数順がディスパッチ側と一致すること
- 必要なら`trace`にSVCイベントが記録されること
