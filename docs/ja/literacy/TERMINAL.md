# 端末の使い方と画面制御

[English](../../en/literacy/TERMINAL.md) | [TTY設定](TTY.md) | [UARTと端末](../reference/devices/UART.md) | [開発時の調査記録](../../history/ja/TERMINAL-DEBUG.md)

PicoNIXでは，**端末への入出力を扱うTTY機能はカーネルが管理**し，**カーソル位置や全画面表示などの画面制御はアプリケーションがANSI/DECエスケープシーケンスで行います**．この2つは独立しているため，TTY設定を戻しても画面表示が元に戻るとは限りません．

## 1．端末と入出力

USB CDCの`/dev/console`，UART1の`/dev/ttyS1`，対応するPico WビルドのWi-Fi端末`/dev/ttyN0`を通じてシェルを操作できます．接続方式や`getty`の詳細は[UARTと端末](../reference/devices/UART.md)と[ネットワーク](../reference/devices/NETWORK.md)を参照してください．

TTYでは入力の行編集（canonical），入力エコー（echo），出力の改行変換（ONLCR）を管理します．パイプや通常ファイル，ソケットはTTYではないため，これらの処理を受けません．

## 2．TTY設定とFDのブロッキング設定

行入力（`icanon`），エコー（`echo`），改行変換（`onlcr`）はTTYごとの設定で，`stty`または`ioctl()`で変更します．一方，`fcntl()`の`O_NONBLOCK`はFDの入出力待機に関する設定です．両者は独立しています．`raw`は`-icanon -echo`の略記であり，POSIXの完全なrawモードではありません．

設定コマンド，`OS_TTY_*`，`OS_TTY_PERSIST`，復元規則と制限事項の正確な仕様は[TTY設定](TTY.md)を参照してください．この文書では，主にアプリケーション側の画面制御を説明します．

## 3．改行と画面表示

| 文字 | 動作 |
| --- | --- |
| `\r`（CR） | 現在行の先頭へ移動 |
| `\n`（LF） | 次の行へ移動 |
| `\r\n` | 次の行の先頭へ移動 |

ONLCRが有効なTTYでは，出力時のLFをCRLFへ変換します．すでにCRLFの並びになっている場合は二重変換しません．これは**カーネルのTTY出力処理**であり，カーソルを任意の位置へ動かす機能ではありません．

画面操作はアプリケーションが出力するエスケープシーケンスを，PC側の端末エミュレータが解釈して実現します．

| シーケンス | 主な用途 |
| --- | --- |
| `ESC[2J` | 画面消去 |
| `ESC[H` | カーソルをホーム位置へ移動 |
| `ESC[?25l` / `ESC[?25h` | カーソルを隠す／表示する |
| `ESC[0m` | 文字属性を初期化 |
| `ESC[?1049h` / `ESC[?1049l` | 代替画面へ移動／通常画面へ戻る |
| `ESC[r` | スクロール領域を初期化 |

C文字列では`ESC`を`\033`と書きます．端末エミュレータによって対応状況やスクロールバックの挙動は異なります．

## 4．全画面アプリの作法

`edit`，`mem`，`gpio`，`mb`などの全画面アプリは，起動時に画面状態を変更し，終了時に元に戻します．概念的には次のように書きます．

```c
printf("\033[?1049h\033[?25l"); /* 代替画面・カーソル非表示 */
/* 対話処理 */
printf("\033[?25h\033[?1049l"); /* 復帰 */
```

**TTYのcanonical/echo/ONLCRは前景タスク終了時にカーネルが保存状態へ復元**します（`stty`や`reset`の意図的な設定変更を除く）．一方，**ANSI/DECの画面状態はカーネルのTTY設定に含まれません**．アプリが正常終了時に復帰処理を行うほか，現行シェルには特定の全画面コマンドの終了・中断後に代替画面解除を試みる補助処理があります．新しい全画面アプリを追加する際は復帰処理も確認してください．

通常のシェルプロンプトで毎回`ESC[?1049l`を送るべきではありません．端末によって保存されたカーソル位置へ戻り，表示が乱れる場合があります．

## 5．Ctrl+C，パイプと端末

前景タスクをCtrl+Cで中断すると，アプリの通常の終了処理が実行されないことがあります．カーネルのTTY設定復元と，画面の復元を区別してください．パイプラインでは`dup2()`によって標準入出力がパイプへ接続される場合があり，`stdout`がTTYとは限りません．パイプに送るデータへ画面制御シーケンスを混入させない設計が必要です．詳しくは[パイプ](PIPE.md)を参照してください．

## 6．`reset`による復旧

```sh
reset
```

`reset`はcanonical入力とechoを有効にし，代替画面解除，文字属性，カーソル表示，スクロール領域，画面の初期化を試みます．`O_NONBLOCK`は変更しません．端末からコマンドを入力できない状態では実行できないため，万能な復旧手段ではありません．

過去のgtkterm・VS Code端末での表示不具合，調査手順，増分ビルドの注意点は[開発履歴](../../history/ja/TERMINAL-DEBUG.md)に移しました．

## 7．`watch`の差分画面更新

`watch [秒] コマンド [引数...]` は，子プロセスの標準出力と標準エラー出力をパイプへ取り込み，実行が完了してから前回と異なる行だけをANSIカーソル移動で再表示します．初回だけ画面を消去し，以後は行末の消去で短くなった表示を補正します．

```sh
watch 1 ps
watch 1 cat /proc/net/memory
```

表示は24行以上の端末を想定した固定領域（見出しを除き20行，各行最大78バイト）に制限します．収まらない出力は最後まで読み捨て，画面下部に`[watch: output truncated]`と表示します．表示内容の比較は行単位であり，制御シーケンスは表示せず，ANSIを使う対話型・全画面型プログラムには対応しません．終了しないコマンドは従来と同じく，その実行が終わるまで更新されません．

子プロセスがパイプへ256バイト以上出力しても停止しないように，`waitpid()`より先にパイプをEOFまで読み取ります．表示用の2画面バッファはユーザプロセスのメモリに確保し，カーネル側に表示履歴は保持しません．

`mem`と`watch`は描画中だけ端末の自動折返しを無効にし，右端を超える表示を次行へ回さず，描画後に元へ戻します．

## 8．画面制御の共通ヘルパー（`userland/lib/screen.h`）

`edit`，`vi`，`mem`，`mb`は，代替画面の開始・終了やカーソル移動に共通の`screen.h`を使用します．`edit`と`vi`，`mb`は端末のカーソル位置応答（DSR，`ESC[6n`）からサイズを取得します．問い合わせは**canonical入力を無効化した後**に行い，応答がなければ80桁×24行を使用します．端末側の対応が必要であり，カーネルがウィンドウサイズを提供するわけではありません．

`edit`と`vi`はRAM・描画負荷を抑えるため最大160桁×60行に制限します．`mb`は従来の52桁×10行のゲームフィールドを端末中央に配置します（ゲームの当たり判定は不変です）．`mem`は現在も16行×16バイトの固定表示です．`pong`と`watch`は，それぞれ複数端末描画と固定バッファを使用するため今回の共通化対象外です．端末サイズ変更中の動的再配置には対応していません．
