# PicoNIXとLinuxの違い

*技術リファレンス*

PicoNIXは，**UNIXの基本原理を学ぶための小規模な教育用OS**です．Linuxの小型版でも，POSIXに完全準拠したOSでもありません．プロセス，ファイルディスクリプタ，デバイスファイル，パイプ，端末，システムコールなどの基本概念を残し，そのほかの仕組みは意図的に省略・簡略化しています．以下は現行ソースコードに基づく説明です．

## 1．プロセス，シグナル，ジョブ制御

| 項目 | Linux | PicoNIX |
|---|---|---|
| プログラムの起動 | 一般に`fork()`と`execve()`などを利用 | 登録済みプログラムを`spawn()`で直接起動．対応するRAMイメージには別の起動処理を用意 |
| アドレス空間 | プロセスごとの仮想アドレス空間 | 固定の物理SRAMスロット．仮想記憶やプロセス間メモリ保護はなし |
| プロセスグループとセッション | POSIXのプロセスグループとセッションを管理 | **POSIXのプロセスグループ・セッションはなし** |
| シグナル | シグナル配送・ハンドラなどを提供 | `kill(pid)`による終了とCtrl+Cによる前景タスクの中断に限定した簡易制御．**一般的なPOSIXシグナル機構はなし** |
| 前景パイプライン | 通常はプロセスグループ単位で制御 | TTYごとに最大3個の前景タスクPIDを管理し，Ctrl+Cで中断．**POSIXのプロセスグループではない** |
| バックグラウンド | シェルのジョブ制御機能など | 基本的な`&`を提供．`jobs`，`fg`，`bg`などの完全なジョブ制御はなし |
| タスク数 | 資源や設定による | **ユーザタスク最大6個**．シェルやサービスも共通の枠を使用し，別に内部idleタスクが存在 |

例えば，`echo hello | cat`はパイプで接続された複数のタスクを起動します．Ctrl+Cによって前景のパイプラインを停止できますが，内部で`setpgid()`などを使っているわけではありません．また，`fork()`で現在のタスクを複製するのではなく，空きスロットへプログラムを直接起動します．

## 2．ユーザ，権限，メモリ保護

PicoNIXには**ユーザアカウント，UID・GID，rootアカウント，ログイン認証，ファイルアクセス権の検査がありません**．概念的にはすべてのプログラムがroot相当ですが，**実際にrootというユーザが存在するわけではありません**．また，Linuxのroot権限（OSのアクセス制御）とCPUの特権モード（ハードウェアの保護機構）は別の概念です．RP2040上のPicoNIXにはユーザメモリをハードウェアで隔離する仕組みもありません．したがって，信頼できない利用者・プログラムを安全に分離する用途には適しません．

カーネルのコードはFlash上でXIP実行します．組み込みユーザプログラムはFlashにPICイメージとして保存され，起動時にSRAMスロットへコピーされます．各24 KiBスロットのうち4 KiBはスタック用です．LinuxのELFロード，仮想記憶，保護されたプロセス空間とは異なります．

## 3．ファイル，ディレクトリ，入出力

PicoNIXにはディスクファイルシステム，書き込み可能な永続Flashファイルシステム，一般的なマウント機構，シンボリックリンク，ファイル所有者管理がありません．VFSは次の種類のノードを公開します．

| パス | 内容 |
|---|---|
| `/tmp`，`/etc` | 共通領域を使う**揮発性RAMファイル**．書き換え内容は再起動で失われる |
| `/dev` | TTY，GPIO，I²C，Pico Wのネットワーク観察・ICMPなどのデバイスインターフェース |
| `/proc` | カーネルやタスクの状態を表示する読み取り専用の仮想情報ファイル |
| `/bin` | 組み込みコマンドの一覧．**ディスク上の実行ファイルではない** |

`/etc`の設定ファイルやHTMLは起動時に初期内容が用意されるRAMファイルであり，永続保存されません．ディレクトリはVFSが公開し，任意の階層を作成する機能はありません．相対パスや`.`，`..`は扱えますが，Linuxと同じファイルシステム機能を備えているわけではありません．

`open()`，`read()`，`write()`，`close()`，パイプ，簡易`FILE`ストリームを使用できます．Cライブラリは64バイトのバッファを持つ小さな実装であり，glibcではありません．LinuxやPOSIXの全システムコール・標準入出力機能は提供していません．

## 4．端末とネットワーク

| 項目 | PicoNIXの仕様 |
|---|---|
| USB CDC | `/dev/console`．Pico・Pico Wで利用可能 |
| UART1 | `/dev/ttyS1`．GP20（TX），GP21（RX）．Pico・Pico Wで利用可能 |
| Wi-Fi Telnet | Pico Wビルドのみ`/dev/ttyN0`．カーネルのTCP 23番サービス |
| TTY設定 | canonical／noncanonical入力，echo，改行変換，非ブロッキング入出力などの簡易実装．**完全なPOSIX termiosではない** |
| TCP・UDP | Pico WのlwIPによる小規模なIPv4ソケットAPI．BSD/POSIX完全互換ではない |
| ICMP・パケット観察 | Pico Wの`ping`，`tcpdump`，`/dev/net/icmp`，`/dev/net/packet`．IPv4の要約と先頭最大16バイトを観察．**Ethernetフレーム全体やlibpcapは扱わない** |

TelnetとUDPデバイス制御サービスには**認証や暗号化がありません**．信頼できる実験用ネットワークに限定してください．通常のPicoにはWi-Fiハードウェアがありません．

## 5．実装上の上限値

次の数値はLinuxの資源制限設定ではなく，**PicoNIXの実装で定めた固定容量**です．システム全体で共有する資源もあります．

| 項目 | 現行の上限・仕様 |
|---|---|
| 対象 | RP2040（Raspberry Pi Pico／Pico W） |
| ユーザタスク | **最大6個**．別に内部idleタスクあり |
| ユーザスロット | **各24 KiB**．うち**4 KiBをスタック用に予約** |
| カーネルSRAM領域 | **56 KiBのアドレス領域を確保**．実コードサイズの測定値ではない |
| ユーザプログラム | PIC形式，`-Oz`最適化 |
| ファイルディスクリプタ | **1タスク当たり16個**（0〜15）．標準入出力，パイプ，ソケットを含む |
| パイプ | **同時に最大2本**．**1本256バイト** |
| RAMファイル | `/tmp`と`/etc`の合計**11個**．**各2,048バイト** |
| RAMファイル名 | `/tmp`または`/etc`直下で**最大27バイトのASCII名** |
| 共有メモリ | `/dev/shm`に**2 KiB** |
| トレース領域 | **16 KiB** |
| ネットワーク予約領域 | **16 KiB**（Pico WではlwIPヒープ・idle／ネットワークスタック等を配置） |
| ユーザTCPソケット枠 | Pico Wで**4個** |
| パケット観察 | Pico Wで**固定16レコード** |
| C標準入出力 | **ストリームごとに64バイトバッファ**．追加の`fopen()`ストリームは**最大4個** |
| TTY | Picoは**2系統**，Pico WはTelnetを含め**3系統** |

これらは各機能の固定容量であり，すべての資源を同時に最大数まで使用できる保証ではありません．詳しくは[メモリ配置](MEMORY-LAYOUT.md)，[ファイルシステム](FILESYSTEM.md)，[TTY](commands/TTY.md)，[ネットワーク](network/NETWORK.md)を参照してください．
