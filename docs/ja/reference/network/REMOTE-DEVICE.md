# リモートデバイス制御（UDP 2000番）

*技術リファレンス*

Pico Wは，**カーネル側のUDP 2000番ポート**で，一部のデバイス操作を提供します．これはユーザプログラム向けのTCP/UDPソケットAPIとは別のサービスです．**認証・暗号化・要求ID・自動再送はありません**．信頼できる隔離された実験ネットワークでのみ使用し，インターネットに公開しないでください．GPIO出力，PWM，LEDマトリクスを変更できるため，危険な駆動機器の停止をネットワーク接続だけに依存させないでください．

## 接続と使用例

既定のAPモードではPicoNIXのアクセスポイントに接続し，`192.168.4.1`を利用します．STAモードではPico Wに割り当てられたIPアドレスに読み替えます．ホストPCのPython 3から次を実行できます．

```sh
python3 host/piconixctl.py read /dev/adc/temp
python3 host/piconixctl.py read /dev/gpio/16
python3 host/piconixctl.py enable /dev/fb
python3 host/piconixctl.py write /dev/fb 183c7effff7e3c18 --hex
python3 host/piconixctl.py disable /dev/fb
```

GPIOピンが予約されている場合，読み取りに失敗することがあります．接続先を変更するときは，コマンド名より前に`--host ADDRESS`を指定します．`--timeout`と`--port`も利用できます．フレームバッファは8バイトのバイナリなので，`--hex`で16進文字列から変換します．連続したLED表示とADCの実験は`python3 host/demo_udp.py --interval 0.2`で試せます．いずれのツールもタイムアウト時に自動再送しません．

## 通信プロトコル

1個のUDPデータグラムに1要求を格納します．**要求の最大長は128バイト**です．サーバは送信元アドレス・ポートに1応答を返します．

| 要求（ASCIIの先頭部分） | 動作 |
|---|---|
| `READ <path>` | デバイスから読み取り，`OK\n`に続けてデータを返す |
| `WRITE <path>\n<payload>` | バイナリを含むデータを書き込む（パスとデータは空白区切りも可能） |
| `ENABLE <path>` | FBを有効化，または許可されたGPIOを出力モードにする |
| `DISABLE <path>` | FBを無効化，または許可されたGPIOを入力モードにする |

成功時は`OK\n`に続く読み取りデータ，または書き込み等の場合は`OK\n`だけが返ります．拒否時は`ERR`の3バイトです．パケットが失われたり無視されたりすると応答がないため，クライアント側でタイムアウトを処理してください．`WRITE`以外の要求は末尾の改行を省略できます．バイナリの`WRITE`では改行で区切り，必要なバイト数を正確に送信してください．

**注意：**受信処理は要求を1件だけ保留します．処理待ちの間に届いた別のデータグラムは破棄される場合があります．要求ID，重複排除，配送保証はなく，応答が失われても書き込みが実行されなかったとは限りません．

## 操作可能なデバイス

| パス | READ | WRITE | ENABLE / DISABLE |
|---|---|---|---|
| `/dev/fb` | 生の8バイト | 生の8バイト（固定長） | LEDマトリクスの動的点灯を有効化／無効化 |
| `/dev/gpio/<pin>` | ASCII `0\n`または`1\n` | ASCII `0`または`1`（末尾改行可） | 出力／入力への切替 |
| `/dev/pwm/1/freq` | 改行付き10進数 | 周波数の10進数 | 非対応 |
| `/dev/pwm/1/a`，`/dev/pwm/1/b` | デューティ値の10進数 | デューティ値の10進数 | 非対応 |
| `/dev/adc/0`，`/dev/adc/1`，`/dev/adc/2`，`/dev/adc/temp` | ASCII形式の測定値 | 非対応 | 非対応 |

GPIOは`pin_gpio()`と明示的な安全確認によって制限されています．**GPIO 23〜28はUDP経由で操作できません**．ほかのピンもPWM，UART，ADC，使用中のLEDフレームバッファに予約されている場合は操作できません．利用可能なピンはファームウェアの設定によって異なります．このサービスは**汎用のリモートVFSではありません**．たとえば`/etc/index.html`を開くことはできません．具体例は[GPIO遠隔制御](REMOTE_GPIO.md)，ローカル側の仕様は[デバイスガイド](../devices/README.md)を参照してください．

## UDP要求を直接送る例

Linuxホスト上のnetcatによる例です（オプションの挙動は実装によって異なります）．

```sh
printf 'READ /dev/adc/temp' | nc -u -w 1 192.168.4.1 2000
printf 'WRITE /dev/pwm/1/freq\n50' | nc -u -w 1 192.168.4.1 2000
```

応答を確実に区別したい場合，特にバイナリ読み取りには`host/piconixctl.py`を利用してください．カーネル側の実装は`kernel/net_service_remote_devctl.c`にあり，タスクのFDや汎用ファイルアクセスを経由せず，既存のデバイスドライバを使用します．実機での電気的動作とWi-Fi接続は別途検証が必要です．
