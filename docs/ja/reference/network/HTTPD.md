# PicoNIX HTTPサーバ

*技術リファレンス*

`httpd`はPico WのTCP 80番で動作するユーザプログラムです．カーネルには組み込まれていません．Pico Wの起動スクリプトで自動起動します．

`GET /`で紹介ページ`/etc/index.html`を表示します．LEDマトリクスは`/fbcheck.html`からタッチ編集でき，サーボとブザーは`/pwm.html`から操作できます．HTTP APIはホストPCの`curl`からも利用できます（PicoNIX内には`curl`コマンドを実装していません）．

| HTTP API | 動作 | POST本文 |
|---|---|---|
| `GET /api/fb` | LEDの8バイトを16進16文字で取得 | — |
| `POST /api/fb` | LEDの8バイトを書き込み，表示を有効化 | `3C42A581A599423C` |
| `GET /api/pwm/freq` | PWM周波数（Hz）を取得 | — |
| `POST /api/pwm/freq` | PWM周波数を設定 | `1000`（8〜100000） |
| `GET /api/pwm/a`, `/api/pwm/b` | デューティ比（%）を取得 | — |
| `POST /api/pwm/a`, `/api/pwm/b` | デューティ比を設定 | `50`または`50.0`（0〜100） |
| `POST /api/tone` | ブザー用PWM1 Aの周波数とデューティを一括設定，`0`で停止 | `0`または`100`〜`5000`（整数Hz） |

Linux側からの例（`HOST`を実際のPico Wのホスト名またはIPアドレスに置換）：

```sh
curl http://HOST/api/fb
curl -X POST --data-binary '3C42A581A599423C' http://HOST/api/fb
curl -X POST --data-binary '1000' http://HOST/api/pwm/freq
curl -X POST --data-binary '50' http://HOST/api/pwm/a
```

`/etc/index.html`，`/etc/fbcheck.html`，`/etc/pwm.html`はPico Wの起動時に初期化されるRAMファイルです．再起動すると編集内容が失われます．`/etc`と`/tmp`は合計11ファイル，各2048バイトまでです．ページを編集する場合は2048バイトの上限を超えないようにしてください．

**制限と安全性：** HTTP/1.0相当の単一接続・逐次処理です．POSTには重複のない有効な`Content-Length`が必要で，本文は最大32バイトです．不正な長さは拒否し，受信途中でTCPが切断された場合は待機を終了します．チャンク形式，HTTPS，認証，複数要求の同時処理，keep-aliveには対応しません．TCP 80をインターネットへ公開せず，信頼できる隔離された実験用ネットワーク内でのみ使用してください．PWM出力には危険なアクチュエータを直接接続しないでください．

Telnet（TCP 23）とUDP 2000番のデバイス制御はカーネル側で処理します．

## ブラウザでページを開けない場合

URLは `http://<Pico WのIPアドレス>/` を指定してください．HTTPSへの自動切替に注意してください．`curl` では取得できてもブラウザでは開けない場合，ブラウザ固有の大きなHTTPヘッダが原因になることがあります．HTTPサーバは最大2048バイトのリクエストヘッダを受け付け，超過時は HTTP 413 を返します．通常のブラウザでは JavaScript を有効にしてください．

## LEDマトリクスの連続操作

スマートフォンではLEDマトリクスを指でなぞると，通過したマスを連続して点灯・消灯できます．最初に触れたマスが消灯していれば描画，点灯していれば消去になります．同じ操作中はマスを反転せず，一定の点灯状態に揃えます．マウスのドラッグ操作にも対応します．画面は即座に更新し，実機への送信は50 msごとに最大1回だけ試みます．前のHTTP通信が終了するまでは次を開始せず，その間の変更は最新の8バイトへまとめます．指を離した後の最終状態も送信対象になります．全点灯・全消灯も同じ送信制限を使います．通信が失敗した場合の自動再送はしません．

## 現在の表示の自動読み取り

ブラウザは約50 msごとにキャッシュを使わず`GET /api/fb`で実機の表示を読み直し，別のプログラムや`curl`による変更も画面へ反映します．タッチ操作中，未送信の描画があるとき，HTTP通信中は読み取りません．GETとPOSTを同時には送信しません．描画のPOSTは最短50 ms間隔で，実際の頻度はPico Wの応答速度によります．


Web画面の操作ボタンは`Clear`（全消灯）と`All`（全点灯）です．`Read`ボタンは設けず，実機から50 ms周期で自動読み取りします．


## Webページ構成とPWM操作

- `/`（`/index.html`）：PicoNIXの紹介とデモへのリンク．
- `/fbcheck.html`：LEDマトリクス制御画面．50 ms間隔の書き込みと50 ms間隔の自動読み取り．
- `/pwm.html`：サーボ（GP19/PWM1 B）・パッシブブザー（GP18/PWM1 A）の切替テスト画面．

PWMページは初期状態では出力しません．サーボのスライダーに触れるとGP19（50 Hz）が自動的に有効になり，「Servo enabled」のチェックでオン・オフを切り替えられます．ブザーの音階ボタンを押すとGP19が自動停止してGP18に切り替わり，離すとブザーが止まります．サーボのパルス幅は0.7〜2.3 ms（0.02 ms刻み），ブザーは262〜523 Hz・デューティ50%です．PWM1 A/Bは周波数を共有し，異なる周波数では同時に使用できません．外部電源のサーボとPicoのGNDを共通にし，サーボの許容パルス幅を確認してください．

Wi-Fi APへスマートフォンからアクセスできない場合は，モバイルデータ通信やVPNを一時停止し，`http://192.168.4.1/`を直接開いてください．

LED描画領域ではタッチスクロール・文字選択を抑制します．領域外の通常操作は維持します．

GP18のブザーとGP19のサーボは同じPWMスライス1を共有するため，ブラウザからの制御要求は順番に送信します．サーボには50 Hzが必要であり，ブザーへの古い要求が後から届くと周波数が変わる可能性があります．動かない場合は`pwmctl status`で周波数とデューティを確認し，サーボの外部電源とGNDの共通接続も調べてください．

Pico Wの紹介ページは`edit /etc/index.html`で直接編集し，Ctrl+Sで保存できます．変更されるのはRAM上の内容であり，再起動すると元に戻ります．
