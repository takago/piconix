# PicoNIX カーネルトレース

*操作ガイド*

PicoNIXは，タスク切り替え，システムコールの開始・終了，周期的なタイマイベントを `/dev/trace` に記録できます．表示には `trace` コマンドを使います．

## 最初に試す

```sh
trace run hello
```

`hello` を起動し，そのプロセスが終了した後で記録を一覧表示します．これが最も簡単な使い方です．表示される主な列は次のとおりです．

| 列 | 読み方 |
|---|---|
| `Time` | 記録時刻（起動からの経過時間） |
| `PID` / `Command` | イベントに関係するタスクとコマンド |
| `TTY` | 使用端末 |
| `Type` | `SYSCALL`，`KERNEL`，`SWITCH`，`TIMER` などの種類 |
| `Function` | 呼び出された処理．末尾の `/` は出口（復帰） |
| `Arg` | 記録できた引数や対象FD・パス（すべての引数ではない） |
| `Ret` | 記録できたシステムコールの結果 |
| `Info` | 読み書きしたデータの一部など補助情報 |

例えば `open` は入口，`open/` は出口です．入口の `Arg` にはパスが最大16バイト表示され，出口では結果を確認できます．パスが長い場合は切り詰められます．`--` はその項目に表示する値がないことを表します．実際のイベント数や時刻は実行状況によって異なります．

次に `trace run ls` を実行すると，`hello` よりもファイル操作に関連するイベントを観察できます．

## コマンド一覧

```text
trace on -s      # システムコールのみ記録（KERNEL・TIMER・SWITCHなし）
trace on         # 記録を消去して開始（関数はSVC内）
trace on -a      # SVC外の選抜関数も記録
trace off        # 記録を停止
trace show       # 記録を停止して全履歴を表示
trace show 3     # 記録を停止してPID 3のイベントを表示
trace follow     # 実行した時点以降の新しいイベントを表示
trace follow 3   # 実行した時点以降のPID 3のイベントを表示
trace run -s hello # helloのシステムコールのみ記録
trace run hello  # helloを起動し，終了後にそのPIDのイベントを表示
trace run python test.py  # Pythonスクリプトの実行を記録
trace run -a ping 127.0.0.1 # SVC外の選抜関数も記録
trace run cat /tmp/test.txt  # 関数計測ビルドでは選抜関数も記録
```

**`trace show`や`trace follow`はトレースの表示操作であり，対象プログラムを起動しません．** 1つの端末しか使えない場合は，`trace run hello`のように`run`を使用すると，起動から終了までを簡単に観察できます．

PIDは10進数で指定します．通常のプロセスには**1〜255のPIDを循環割り当て**し，0はアイドルタスク用です．実行中のプロセスや，`waitpid()`で未回収の終了通知と同じPIDは割り当てません．`trace_event_t`のPIDは従来どおり8ビットで，レコード長は32バイトです．PIDは再利用されるため，長時間保持した記録に対する`trace show PID`は異なる時点のプロセスを含む場合があります．`trace run`は起動前の記録を読み飛ばします．

**PID指定は表示フィルタ**であり，カーネルがそのプロセスだけを記録するわけではありません．`trace on` を実行してから観察対象のプログラムを動かしてください．`show` は表示前にトレースを停止します．`follow` は開始時に保存済みのイベントを読み飛ばし，実行した時点以降のイベントだけを表示します．記録は停止しません．

`SWITCH` イベントでは**切り替え先**のPID（イベントの `value`）をフィルタに使います．通常のSVCイベントでは実行タスクのPIDを使います．`follow` は前景で動作し，別端末から `trace off` を実行すると残りのイベントを表示して終了します．Ctrl+Cでも中断できます．表示速度が追いつかない場合は上書き件数を通知します．

## コマンドを起動してトレースする（`trace run`）

`trace run command [args...]` は，指定したコマンドを**新しく起動**し，終了を待ってからそのPIDのイベントを表示します．PIDを事前に調べる必要はなく，プログラムの出力とトレース一覧も同時には表示されません．`/bin` に登録されたコマンド名，`/bin/名前`，または `/tmp/名前` またはカレントディレクトリの `./名前` の実行イメージを指定できます．`/tmp` の実行イメージには引数を渡せません．

```text
trace run hello
trace run ls
trace run python test.py
trace run /tmp/a.out
trace run ./a.out
```

起動前に`/dev/trace`の読み出し位置を末尾まで進めるため，以前のイベントは表示されません．記録が停止している場合は開始し，子プロセス終了後に停止します．既に記録中の場合は**既存の記録を消去せず，記録状態も維持**します．指定した子PIDだけを表示するため，同時に動く別プロセスは一覧に含まれません．

トレースは16 KiB（512件）リングバッファ（`0x20038000`〜`0x2003BFFF`の専用RAM領域）に保存されます．実行が長い場合は古いイベントが上書きされ，起動直後のイベントも失われる可能性があります．`trace run` は直接起動したプロセスだけを絞り込み，孫プロセスを自動追跡しません．ゲームやREPLなど，終了しないプログラムでは終了するまで一覧は出ません．

## 応用：選択カーネル関数の自動トレース

通常ビルドは選抜したカーネル関数の入口・出口の計測機能を含みます（ビルド時の既定値はON）．ただし，起動直後のイベント記録はOFFです．記録するときに `trace on` または `trace run` を使用します．

```bash
./tools/build_sdk.sh --no-flash -DPICO_BOARD=pico -DPICONIX_KERNEL_FUNCTION_TRACE=ON
```

ビルド時の既定値はONです．計測なしの軽量ビルドが必要なら`-DPICONIX_KERNEL_FUNCTION_TRACE=OFF`を指定してください．既存のCMakeキャッシュには以前の設定が残る場合があります．

```text
trace on -s          # システムコールの入口・出口だけ
trace on             # 通常イベント + SVC内の選抜関数
trace on -a          # 通常イベント + 全コンテキストの選抜関数
trace follow         # 以降の記録を表示（表示用コマンド）
trace show           # 停止して記録を表示
trace run -s hello   # helloのシステムコールだけ記録
trace run hello      # コマンドを起動してSVC内の関数も記録
trace run -a hello   # 全コンテキストの関数を記録
```

`-s`は**記録時点で**SYSCALL入口・出口だけを残し，KERNEL・TIMER・SWITCHは記録しません．`-a`は**選抜されたカーネル関数**の記録コンテキストだけを拡張します．通常イベントの種類は変えません．
SVCで呼び出された関数には呼出元PIDを付け，割込み・非同期カーネル処理にはPIDを付けず「-」と表示します．
`trace follow PID`と`trace show PID`はPIDなしのイベントを表示しません．
`trace run -a`でも記録は全コンテキストですが，終了後の表示は起動したPIDに限定するため，非同期処理は`trace on -a`と`trace follow`で観察してください．

### 記録モードの選択

| 操作 | 記録されるイベント |
|---|---|
| `trace on -s` / `trace run -s` | SYSCALLのみ（入口・出口） |
| `trace on` / `trace run` | SYSCALL，TIMER，SWITCH，SVC内の選抜KERNEL関数 |
| `trace on -a` / `trace run -a` | 通常イベント＋全コンテキストの選抜KERNEL関数 |

`trace run`は指定プログラムの終了後にPID別の結果を表示し，実行前の記録状態・モードを復元します．`trace on`はリングを初期化して記録を開始し，`trace off`は記録を停止します．`-s`は単なる表示フィルタではなく，リングバッファの消費も抑えます．

### 高頻度の状態確認と関数計測

`-finstrument-functions` は指定したソースファイルの各関数に入口・出口フックを挿入します．周期的な待機確認まで計測すると，`trace on -a` ではネットワーク状態確認イベントがリングバッファを埋めることがあります．

そのため，TCP接続状態・受信可能性などの確認，TTY受信可能性の確認，スケジューラの待機解除確認には `NO_TRACE`（`no_instrument_function`）を指定し，関数計測フック自体を省略しています．これらの関数は `TRACE_MATCH` の表示対象にも含めません．一方，`tty_input_char()`，ソケットのデータ転送，`task_unblock()`，`SYSCALL`，`TIMER`，`SWITCH` は引き続き観察できます．


計測を有効にする8個のカーネルCソースでは，**`TRACE_MATCH` に登録された51関数だけ**を計測対象とし，その他の関数定義には `NO_TRACE` を付けています．これにより，表示されない関数にまで入口・出口フックを挿入する従来の無駄を減らします．定期ポーリング処理は継続しますが，関数計測の負荷は削減できます．関数を追加するときは，`TRACE_MATCH` への登録と `NO_TRACE` の有無を点検し，`test_kernel_trace_targets.py` で分類漏れを検査してください．

`NO_TRACE` は呼出先の関数へは継承されません．また，ポーリングそのものが止まるわけではありません．UART1入力の割込み処理や `tty_input_char()` の計測負荷については，実機の連続入力で検証してください．

### 関数一覧とシンボル表の役割

関数計測を有効にしたビルドでは，`kernel/kernel.c`，`kernel/adc.c`，`kernel/i2c.c`，`kernel/pwm.c`，`kernel/gpio.c`，`kernel/fb.c`，`kernel/net_socket.c`，`kernel/net_capture.c` にコンパイラの`-finstrument-functions`が適用されます．計測フックが呼ばれた後，`kernel/kernel.c`の`TRACE_MATCH`一覧で記録する関数を絞ります．別のCファイルで定義した関数も，内部ヘッダに適切な宣言があれば参照できます．選抜した51関数には計測フックが入り，`TRACE_MATCH`で記録名を選択します．記録OFF時も対象関数のフック負荷は残りますが，計測対象外の関数には`NO_TRACE`を指定しています．

一方，`mem -s kernel`で参照するカーネルシンボル表は，リンク済みELFのシンボルから生成します．関数名とアドレスの参照が目的であり，トレース対象を決める一覧ではありません．関数一覧の重複・所在・計測対象の整合性は`tools/test_scripts/test_kernel_trace_targets.py`で検査します．

対象関数には`os_svc_dispatch()`（SVCディスパッチャ）と`task_unblock()`（待機タスクの再開）も含まれます．前者は既存の`SYSCALL`イベントと重複しますが，カーネル関数としての入退場を見る目的で追加しています．後者はSVC外でも呼ばれるため，観察には`trace on -a`が必要な場合があります．`tty_input_char()`も試験的に対象へ追加しました．USB CDC・Telnetの入力に加え，UART1受信割込み内でも1文字ごとに呼ばれます．通常の関数記録はSVCに限定されるため，入力経路の観察には`trace on -a`を使用します．割込み中の記録負荷とリングバッファの上書きに注意し，UART1での連続受信と文字欠落を実機で確認してください．PIDを持たない割込みイベントは`trace run -a`のPID別表示には含まれません．

対象関数はVFS・FD管理，RAMファイル，TTY，GPIO，ADC，I²C，PWM，フレームバッファ，TCP/UDP操作と，ICMPデバイスの`net_echo_write`，`net_echo_read`，`net_echo_close`です．`net_capture_poll`と`echo_received`は対象外です．
コンパイラの最適化により一部の呼び出しがインライン化される場合があります．また，計測対象外の関数は記録されません．

記録形式は32バイト固定，共通リングバッファは16 KiB（512イベント）です．関数名は最大16バイトで切り詰められます．
関数の入口・出口は通常`関数名`／`関数名/`と表示します．**同一時刻・同一PID・同一関数で，入口と出口が連続した場合**だけ，表示時に`(関数名)`の1行にまとめます．入れ子の呼び出しや途中に別イベントがある場合，時刻が異なる場合はまとめません．記録内容とバッファ消費量は従来どおりです．`trace follow`では表示のために最大1件の入口イベントを一時保留し，新しいイベントが途切れたら単独行として表示します．PID別に表示用の字下げを行います．ただし，割込みイベントはPIDなしの共通表示となり，割込みによる入れ子やバッファ上書きが起きた場合は字下げが正確な呼出スタックを表さないことがあります．
`-a`は記録量と処理負荷を増やします．トレースバッファは割込み禁止区間で保護しますが，実機での負荷・タイミングは確認してください．
従来の`trace kernel`は廃止しました．


### カーネル関数とシステムコールの階層表示

`os_svc_dispatch()` を関数トレース対象に含めたビルドでは，`SYSCALL` の入口・出口をその内側へ字下げして表示します．例えば `os_svc_dispatch` → `write` → `vfs_rw` → `write/` → `os_svc_dispatch/` の順に，関数の入れ子関係を追えます．関数計測を無効にしたビルドでは，従来どおりシステムコールを最上位に表示します．字下げはイベントをもとに再構成するため，イベント欠落や割込みを挟む場合は厳密な呼出しスタックとは限りません．

`os_svc_dispatch/` はディスパッチャのC関数からの復帰を表し，例外復帰の完了そのものを保証しません．追加の `SVC_ENTER`／`SVC_LEAVE` 境界イベントは記録しません．

表示上のPIDが直前の表示行から変わると，その行の直前にASCIIのハイフン（`-`）による区切り線を挿入します．最初のイベントの前には挿入しません．PIDフィルタで除外したイベントは比較に含めず，連続した関数の入退場を1行にまとめた場合も，実際に表示した行だけを比較します．`SWITCH` 行は切替先PIDを表示するため，区切り線は実際のコンテキスト切替位置を厳密に示すものではありません．ANSI制御文字は使用しません．

## 記録される内容

| イベント | 意味 |
|---|---|
| `SWITCH` | タスク切り替え（表示するPIDは切替先） |
| `read` / `read/` など | システムコールの入口・出口（実際のコール名で表示） |
| `TICKx1K` | 1ms周期のSysTickを1,000回数えるごとの記録 |
| `vfs_rw` / `vfs_rw/` など | 対象カーネル関数への入退場（実験機能） |

表示には時刻，PID，コマンド名，TTY，Function，Arg，Ret，Infoの列があります．トレース表示コマンド自身のシステムコールと関連するタスク切り替えは記録対象から除外されます．

## 追加の操作例：システムコールとタスク切り替え

```text
trace run hello
trace run ls
```

各コマンドが終了すると，そのプロセスのイベントが表示されます．`関数名`と`関数名/`を対にして，どのシステムコールが呼び出されたかを観察してください．`SWITCH`はタスク切り替えを表し，表示対象PIDは切り替え先です．

継続的な記録を調べる場合は，`trace on`で開始し，別のコマンドを動かしてから`trace show`で確認します．`trace show`は記録を停止します．長時間の実行では古いイベントがリングバッファから失われることがあります．

## 内部仕様：`/dev/trace` のバイナリ形式

`include/piconix_trace.h` の `trace_event_t` に定義された**32バイト固定長レコード**を返します．カーネルは**16 KiB（512件）**のリングバッファに保持し，満杯になると古い記録を上書きします．

- `tick`：起動からの経過時間（ms）
- `kind`：下位6ビットがイベント種別，上位2ビットがTTY（0=console，1=ttyS1，2=ttyN0）．イベント種別
- `pid` / `program_id`：タスクIDとアプリID（TTY情報も符号化）
- `file_id`：内部デバイス／ファイルID．不明・対象なしは-1
- `value` / `detail`：イベントに応じたシステムコール番号，引数，結果，切り替え先など
- `data[16]`：`open()`入口（失敗する場合も含む）と成功時の出口におけるパス，または成功した`read()` / `write()`の先頭16バイト．NUL終端は保証されません

`open`のENTER行の`Arg`には開こうとしたパス（最大16バイト）が表示されます．`open/`のEXIT行では成功したFDに対応するパスを表示します．失敗時のEXIT行も，ENTERで記録したパスを使用します．無効なポインタや空のパスを取得できない場合，ENTER行は`path`と表示します．

表示コマンドは記録されたopen情報からPID・FDとパスを対応付けます．古いopenイベントが上書きされた場合は，ファイルIDなどを表示します．長いパスや転送データは切り詰められ，バイナリデータは表示用にエスケープされます．

## タイミング・制約・注意点

SysTickは1ms周期，通常のタイムスライスは10msです．sleepでの起床時には1ms単位で再スケジューリングされます．トレースにはオーバーヘッドがあります．ブロッキング`read()`のEXITは待機開始時ではなく，入力が届いて処理を完了する時点で記録されます．PIDフィルタは表示だけなので，リングバッファの容量消費は減りません．

### デバイス名とID

固定デバイスのIDとパスは，`include/device_names.h`を通じてカーネルVFSと`trace`で共有します．`trace`は対応するパスを表示し，未知または動的なデバイスでは`id=N`にフォールバックします．TTY列は`console`，`ttyS1`，`ttyN0`を区別します．`ls -l`では，デバイスノードのID，プログラムID，RAMファイルのスロット番号を表示します．実際に開いているFDは`/proc/task/<pid>`や`lsof`で確認できます．TTY情報の格納位置を変更したため，旧ファームウェアのバイナリトレース記録と混在させないでください．

表示列は `Time | PID | Command | TTY | Type | Function | Arg | Ret | Info` です．`Function`は関数入口の`name`と復帰の`name/`を表示します．`Arg`は従来の対象FD・パス・終了ステータスなどの記録済み情報であり，全引数を列挙するものではありません．`Ret`はシステムコール復帰時の記録値で，カーネル内部関数の戻り値は記録していません．`Info`は入出力プレビューや切替先などの補助情報です．取得されない項目は`--`と表示します．`Type`は`SYSCALL`，`KERNEL`，`SWITCH`，`TIMER`，`OTHER`を区別します．`exit`の`Ret`に表示される値は通常の関数戻り値ではなく，トレースレコードの終了処理結果です．
