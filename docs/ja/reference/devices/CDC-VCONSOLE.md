# CDC仮想コンソール（CDC Virtual Console）

USB CDCの物理ポートを増やさず，PicoNIXの**独立した2つの論理TTY**を1本のUSB CDC上で切り替える機能です．UART1，Telnet，MCP用PTYの番号や入出力には変更を加えません．

| 論理コンソール | TTY番号 | デバイス | 起動 |
|---|---:|---|---|
| Console 0 | 0 | `/dev/ttyV0` | 起動時からシェルが動作 |
| Console 1 | 4 | `/dev/ttyV1` | 初回切替時にシェルを起動 |

`/dev/console`は**現在入力先として選択されているCDC仮想コンソール**を指します．`open()`時点でTTY 0またはTTY 4に解決し，開いたFDの接続先はCtrl+Tで切り替えても変わりません．シェルの標準入出力と`/dev/tty`も各タスクの端末に固定されます．`/dev/ttyV0`と`/dev/ttyV1`は切替に依存しない固定名です．

USB CDC端末で**Ctrl+T**（制御コード`0x14`）を押すと，Console 0とConsole 1が交互に切り替わります．切替時にアプリは終了せず，非表示側のシェルや`top`なども実行を続けます．Ctrl+Tは画面切替専用で，アプリには渡されません．空きタスクスロットがなく初回のシェルを起動できない場合は，ベルを出して元の画面にとどまります．

## 使い方

1. USB CDCコンソールで通常どおりPicoNIXを起動します．
2. Console 0で`top`を実行します．
3. Ctrl+TでConsole 1へ切り替え，`tty`で`/dev/ttyV1`が表示されることを確認します．
4. Console 1からゲームやPythonを起動し，Ctrl+Tで`top`へ戻ります．

TTYごとのcanonical入力，echo，ONLCR，Ctrl+C，前景タスク，入力キューは独立しています．画面も80×24の固定サイズで個別に保持します．画面の切替表示はUSBの送信キューを小分けに利用して復元するため，切替直後に全画面表示が完了するまで少し時間がかかる場合があります．


## 縦2画面表示（Dual Mode）

USB CDC端末で**Ctrl+G**（`0x07`）を押すと，従来の単画面表示と縦2画面表示を切り替えます．2画面表示では，Console 0とConsole 1の80×24画面を上下に配置し，各画面の前に独立したタイトルを表示します．`[/dev/ttyV0]`と`[/dev/ttyV1]`のタイトルは80列全幅の反転表示バーとし，選択中のタイトルには太字の`ACTIVE`を加えます．最下部の操作案内も80列全幅の反転表示バーで，`C-Left/Right: V0/V1/Dual  C-Up/Down: Focus (Dual)  C-T/G: Legacy`と操作を表示します．**Ctrl+T**は両モードで入力先を切り替えます．タイトルと操作ガイドはスクリーンバッファに書き込まれません．

2画面表示には**80列×51行以上**のANSI対応ホスト端末が必要です．上段の見出しが1行目，Console 0が2〜25行目，下段見出しが26行目，Console 1が27〜50行目，ガイドが51行目です．アプリのANSI制御は各スクリーンバッファに解釈してからUSBへ再描画するため，片方の`clear`，スクロール，カーソル移動がもう一方を直接消しません．この描画はUSB送信キューを小分けに使います．再描画中はホスト端末のカーソルを隠し，両画面の描画を終えてから選択中のTTYのカーソル位置・表示設定を復元するため，カーソルのちらつきを軽減します．

単画面表示ではホスト側の広い端末に長い行を直接出力できますが，**2画面表示では記録された80列×24行のみ**を表示します．複雑なANSI制御（色，スクロール領域など）は既存の簡易画面パーサの対応範囲に限られます．また，2画面表示中は画面更新時に描画データ量が増えます．ホスト端末が51行未満の場合は正常な配置を保証できません．Ctrl+GはUSB CDC側で予約され，アプリには渡されません．

## 80列のスクリーンバッファと長い行

画面バッファの文字位置は80×24で固定し，行の80列目に到達した後の文字は**自動折り返しせず記録を省略**します．改行やカーソル移動後は次の位置から記録します．この制御はTTYの行入力ではなく画面パーサ側で行います．USB CDCへ送る文字列には80列の制限を設けないため，ホスト端末を120列に広げた場合，`trace`の長い行もそのまま表示できます．ただし，Ctrl+Tで切り替えて戻った場合，復元できるのは記録済みの80×24部分のみです．この制約はPTYの`/dev/pts/0.screen`にも適用されます．

TTYのデバイス番号と行規律の対応は共通ヘルパーで処理し，CDC，UART1，Telnet，PTYで入力・エコー・端末設定・前景管理の既存ロジックを共用します．スクリーンバッファはTTYとは独立した表示状態です．

## 画面再現の範囲と注意

- 画面状態は既存のPTYで使う最小ANSI解釈を再利用しています．ASCIIの文字配置，改行，カーソル移動，画面消去，反転表示を復元します．
- **ANSI端末の完全なエミュレータではありません**．カラー・スクロール領域・複雑な制御列などは非表示画面からの再描画時に完全再現できません．代替画面終了時の以前の通常画面履歴の完全復元も未対応です．
- Ctrl+TはUSB CDC経路だけで有効です．UART1，Telnet，`/dev/pts/0`では切替キーを奪いません．端末ソフトがCtrl+Tを横取りする場合は，そのソフトのキー割当てを確認してください．
- 2番目のシェルも既存の6つのユーザタスクスロットを1つ消費します．追加の管理タスク，システムコール，ユーザ用RAMスロットはありません．
- `/dev/trace`のイベント形式はTTY番号を2ビットで記録するため，TTY 4はTTY 0（USB CDC）と同じトレースタグになります．実際のタスクはPIDで区別できます．

### Ctrl＋カーソルキー（代替操作）

USB CDCの端末がxterm形式の制御シーケンス（`ESC [ 1 ; 5 A/B/C/D`）を送信できる場合，**Ctrl＋→**で`ttyV0単画面 → ttyV1単画面 → 縦2画面 → ttyV0単画面`を循環し，**Ctrl＋←**で逆順に循環します．縦2画面中だけ**Ctrl＋↑**は`/dev/ttyV0`，**Ctrl＋↓**は`/dev/ttyV1`を入力先にします．単画面中のCtrl＋上下は画面を変更しません．縦2画面から単画面へ移る際には，その単画面のTTYが入力先となります．従来のCtrl+T／Ctrl+Gも引き続き使用できます．

通常の矢印キーとESCキーはアプリへ渡します．不完全なシーケンスは短時間後に元のTTYへ渡します．ホスト端末やVS CodeのキーバインドによってはCtrl＋矢印がPicoNIXへ送られない場合があるため，その場合はCtrl+T／Ctrl+Gを使用してください．
