# PicoNIX デバイスガイド

*技術リファレンス*

全ディレクトリとノードの一覧，アクセス権，RAMファイルの制限は[ファイルシステムとノード一覧](../FILESYSTEM.md)を参照してください．

PicoNIXの`/dev`は仮想デバイスファイルです．RAM上にファイルを作るのではなく，`open()`，`read()`，`write()`などを通じてカーネルが周辺機器を操作します．

## デバイス一覧

| デバイス | 内容 |
|---|---|
| `/dev/console` | 主コンソール（USB CDC） |
| `/dev/ttyS1` | UART1端末 |
| `/dev/ttyN0` | Wi-Fiビルド時のネットワーク端末（[NETWORK.md](../network/NETWORK.md)参照） |
| `/dev/net/wifi` | STA制御（`echo restart > /dev/net/wifi`）．非Wi-Fiビルドでは存在せず，APモードではrestart不可 |
| `/dev/net/packet` | IPv4パケット情報を読み取る（TCP/UDP/ICMP，データ先頭16バイト，Pico W専用） |
| `/dev/net/icmp` | ICMP Echo専用の排他的な読み書きデバイス（Pico W専用） |
| `/dev/rand` | 暗号用途には使えない疑似乱数（読み取り専用，1回の`read()`につき最大4バイト） |
| `/dev/gpio/fb` | 8×8 LEDマトリクス用64bitフレームバッファ |
| `/dev/gpio/` | `pins.h`でGPIO指定されたピン |
| `/dev/adc/` | `pins.h`でADC指定された入力および内部温度センサー |
| `/dev/pwm/` | `pins.h`でPWM指定された出力と共通周波数 |
| `/dev/i2c/1` | I²C1マスター（GP26 SDA，GP27 SCL） |
| `/dev/mem` | RAM・Flashの読み出し，タスク・SHM・RAMファイルデータ領域の制限付き書き込み |
| `/dev/shm` | 全タスク共通の2 KiB共有RAM．`read()`，`write()`，`lseek()`でアクセス |
| `/dev/trace` | トレースイベントのバイナリ読み出し |

## 8×8 LEDフレームバッファ

PicoNIXは，GP0～15に接続した単色8×8 LEDマトリクス用のフレームバッファを提供します．**デバイス名は`/dev/gpio/fb`**です．`/dev/fb`や`/dev/fb0`ではありません．USB CDCを主コンソールとして使用する標準構成を想定しています．

### 表示データの形式

表示データは**64bit（8バイト）**です．1行を1バイトで表し，`buffer[0]`～`buffer[7]`はそれぞれGP8～GP15の行に対応します．各バイトのbit0～7はGP0～GP7の列に対応し，**1が点灯，0が消灯**です．`/proc/fb`の文字表示ではbit7が左端，bit0が右端になります．

カーネルはSysTickで**1msごとに1行**を走査し，8行を約8ms（**約125Hz**）で更新します．輝度調整機能はありません．行切替時には一度アノードを消灯してゴーストを抑制します．実際の[LED配線・極性・表示座標](../hardware/WIRING.md)と[ピン配置](../hardware/PINS.md)はハードウェアリファレンスで確認してください．

### 初めて表示する場合の確認手順

[LEDマトリクスの配線と安全上の注意](../hardware/WIRING.md)を確認してから，次の順に試します．

```sh
fbctl test
cat /proc/fb
fbctl off
```

最初のコマンドはハートを表示し，次のコマンドで8行の点灯状態を文字で確認します．`fbctl off`は表示を停止し，GP0～15を通常のGPIOとして使える状態に戻します．**`cat /proc/fb`は保存された8バイトを表示するので，配線が誤っていても正しいパターンを表示し得ます**．実際のLEDの点灯位置は目視で確認してください．

### 読み書きと制御

`open("/dev/gpio/fb", O_RDWR)`で開き，**`read()`と`write()`は必ず8バイト単位**で実行します．8バイト以外の要求はエラーになります．データの読み書きと表示の有効・無効は別の操作です．

| `ioctl()`コマンド | 動作 |
|---|---|
| `OS_FB_ENABLE` | LED表示を有効化し，GP0～15をフレームバッファ用に確保 |
| `OS_FB_DISABLE` | 消灯してGP0～15を入力に戻し，確保を解除 |
| `OS_FB_STATUS` | 有効なら1，無効なら0を返す |

これらの定数は`include/piconix.h`に定義されています．表示はファイルを`close()`しても継続します．表示を終了してGPIOを解放するには，明示的に無効化する必要があります．**表示が有効な間はGP0～15に対する通常のGPIO操作が`OS_EBUSY`で失敗**します．既に開いていたGPIOファイルにも適用されます．

### fbctlコマンド

```sh
fbctl status    # /proc/fb の状態と8×8パターンを表示
fbctl on        # 表示を有効化
fbctl clear     # 表示データをゼロにする
fbctl test      # ハートを3回点滅（最後は表示したまま）
fbctl off       # 消灯し，GPIOを解放
cat /proc/fb    # 状態をテキストで確認
```

`fbctl status`は`/proc/fb`の情報を表示します．`/proc/fb`の各行は`#`が点灯，`.`が消灯を表します．`fbctl clear`は表示データを消去しますが，表示の有効・無効は変更しません．

`kitesys`は数字をLEDに表示し，GP16/17のボタンで表示位置を動かすデモです．GP18のブザーも使用します．起動時にフレームバッファを有効化し，終了後も表示は維持されます．必要に応じて`fbctl off`で停止してください．

**電気的注意：** LEDマトリクスには電流制限と適切な駆動回路が必要です．[配線と電気的注意](../hardware/WIRING.md)を確認してください．

### 対話型フレームバッファエディタ（`fbed`）

`fbed` は`/dev/gpio/fb` の8×8，64bit（8バイト）フレームバッファを編集します．画面の1行は1バイトで，左端の画素がbit7です．現在の内容を読み込み，編集のたびに8バイトを書き戻します．

```text
piconix# fbed
```

| キー | 動作 |
|---|---|
| ↑／↓／←／→ | 編集画素の移動 |
| Space | 選択画素のON/OFF反転 |
| `c` | 全画素を消す |
| `q` | 終了 |

行の右側に各バイトを16進数で表示します．起動時にフレームバッファ表示を有効にし，終了後も描画内容と表示状態は保持されます．LED表示中はGP0～GP15が占有されます．表示を停止してGPIOを解放するには`fbctl off`を実行してください．

## GPIO

GPIOとして使用できるピンは`kernel/pins.h`の`GPn_MODE`で決まります．標準ピン配置と予約の詳細は[ピン割当](../hardware/PINS.md)にあります．`ls /dev/gpio`で一覧を確認できます．GPIOの値・方向・プルアップ／プルダウンは既存のGPIOデバイスインターフェースから操作します．ADC・PWM・UARTに割り当てたピンはGPIO一覧に現れず，GPIOとしての操作も拒否します．

### 対話型GPIOエディタ（`gpio`）

`gpio`は，実際のGPIO状態を表示しながら操作するツールです．USB CDCまたはUART1のANSI対応端末で`gpio`を実行します．表示は約50 msごとに更新されます．

#### `gpio` 対話画面

GPIOの状態を8行×4列（左から31〜24，23〜16，15〜8，7〜0）に並べて表示します．存在しない／対象外の位置は `---` となり，選択できません．矢印キーで画面上の方向に移動します．`i` 入力，`o` 出力，`h` HIGH，`l` LOW，`SP` 出力反転，`u` プルアップ，`d` プルダウン，`n` プルなし，`q` 終了です．`h/l/SP` は出力ピンのみ，`u/d/n` は入力ピンのみで有効です．

`[FB]`，`[PWM]`，`[UART-TX]`，`[UART-RX]` などの表示は，カーネルが現在検出した割当てを示します．これらは選択して状態を確認できますが，設定変更はできません．FBの使用を解除すると，状態表示も自動更新されます．

起動時のGPIO既定値：GP25は出力（LOW），GP16・GP17は入力（プルアップ）です．`gpio`コマンドで変更できます．

**端末の注意：** `fbed`と`gpio`はどちらもANSI端末と文字単位入力が必要です．VS CodeのSerial Monitorを使う場合は，端末側の行入力機能を無効にしてください．

カーネルが提供するUDP 2000番の遠隔操作については，[リモートデバイス制御](../network/REMOTE-DEVICE.md)を参照してください．

## ADC・温度センサー

既定の割り当ては次のとおりです．

| デバイス | 入力 | 出力 |
|---|---|---|
| `/dev/adc/0` (disabled) | GP26 | 12ビットADC値（0～4095） |
| `/dev/adc/1` (disabled) | GP27 | 12ビットADC値（0～4095） |
| `/dev/adc/2` | GP28 | 12ビットADC値（0～4095） |
| `/dev/adc/temp` | RP2040内蔵温度センサー | 摂氏の概算値 |

```sh
cat /dev/adc/2
cat /dev/adc/temp
watch 1 cat /dev/adc/temp
```

ADC値は最初の`read()`で測定し，十進テキストとして返します．短い`read()`で一部だけ取得した場合は残りを読み出せます．値を最後まで読み切ると，次の`read()`で新たに測定します．温度は基準電圧3.3 Vを仮定した概算値で，精密な温度計測には向きません．GPIO26～28のモードをGPIOに変更すると，対応するADCデバイスは公開されません．内部温度センサーはピン設定とは独立です．

## PWM

既定ではGP18とGP19をPWM出力に割り当てます．両方とも同じPWMスライスを使用するため，**周波数は共通**ですがDuty比は個別に設定できます．起動時は**1 kHz，両方ともDuty 0%**です．

PWMスライス1のチャネルA（`/dev/pwm/1/a`）はGPIO18，チャネルB（`/dev/pwm/1/b`）はGPIO19に対応します．

```sh
cat /dev/pwm/1/freq
cat /dev/pwm/1/a
cat /dev/pwm/1/b
echo 2000 > /dev/pwm/1/freq
echo 50 > /dev/pwm/1/a
echo 0 > /dev/pwm/1/a
```

`/dev/pwm/1/freq`は8～100000 Hzの整数，`/dev/pwm/1/a`と`/dev/pwm/1/b`は0～100%のデューティ比を小数第1位まで指定できます（例：`7.5`）．読み取り時は`7.5`のように小数第1位まで表示します．周波数にはハードウェアの分周比とカウンタ範囲による丸め誤差が生じ得ます．PWM出力に割り当てていないピンのデバイスは公開されません．

## I²C1

GP26（SDA）とGP27（SCL）はI²C1専用です．`/dev/i2c/1`を通じて利用でき，`i2cctl scan`で接続機器を調べられます．`bh1750 5`は照度センサの測定例です．[配線とプルアップ抵抗](../hardware/WIRING.md)はハードウェア資料，C言語・Pythonからの操作は[I²C1ガイド](I2C.md)を参照してください．

## UART・コンソール

主コンソールはUSB CDCのみです．UART0コンソール構成はサポートしていません．UART1は`/dev/ttyS1`で利用し，`getty /dev/ttyS1 sh &`で別のShellを起動できます．詳細は[UART.md](UART.md)，[UART配線](../hardware/WIRING.md)を参照してください．

## 制限と注意

- ADC・PWM・I²CとGPIOは同じピンで同時には使用できません．
- GP18とGP19のPWM周波数は独立に変更できません．
- `/dev/mem`はFlashとSRAMの読み取りに対応します．書き込みはユーザタスクスロット（0x2000E000〜0x20031FFF），SHM（0x20032000〜0x200327FF），RAMファイルのデータ領域に限ります．カーネルの一般領域，トレース，Wi-Fi予約領域，Flashの書き込みは禁止です．実行中タスクのコードやデータを書き換えると動作が破壊される可能性があります．
- `/dev/trace`はバイナリイベントを返します．利用方法は[TRACE.md](../../guides/TRACE.md)を参照してください．
- ドライバは`kernel/gpio.c`，`kernel/adc.c`，`kernel/pwm.c`に分離しています．FD管理は`kernel/kernel.c`が担当します．
