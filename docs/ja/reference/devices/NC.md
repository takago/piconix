# nc（netcat）と通信の終了

[概要](../../literacy/README.md) | [English](../../../en/reference/devices/NC.md) | [パイプ](../../literacy/PIPE.md)

PicoNIXの`nc`は数値IPv4アドレスを使う簡易TCP/UDPクライアント・待受プログラムです．DNS名，汎用的なnetcatのすべてのオプションには対応しません．

以下はAPモードの例です．Pico Wは`192.168.4.1`，接続したLinux PCは`192.168.4.2`（単一クライアント構成でのDHCP割り当て）を想定します．STAモードでは実際のIPアドレスに読み替えてください．

```sh
nc 192.168.4.2 12345
nc -l 12345
nc -u 192.168.4.2 12345
nc -u -l 12345
```

## 標準入力のEOFで終了する

UDPの単発送信，およびTCPの送信方向の半閉鎖には`-N`を指定できます．

```sh
echo hello | nc -u -N 192.168.4.2 12345
```

UDPでは，`-N`により標準入力がEOFになったときに`nc`を終了します．TCPでは，`-N`によりEOFで送信方向だけを`shutdown(SHUT_WR)`して受信を継続します．相手側からのEOFや接続終了は，双方の送受信の状態に依存します．

UDPにはTCPのFINに相当する接続終了通知がありません．相手のUDP `nc`を終了しても，PicoNIX側が自動終了しないのは正常です．対話利用を終えるときはCtrl+Cを使ってください．

## Ctrl+C

端末で前景実行中の`nc`はCtrl+Cで中断できます．これはPOSIXの`SIGINT`ではなく，カーネルが対象タスクを終了するPicoNIX独自の簡易方式です．FDとソケットの後始末はカーネル側で行います．パイプラインの場合は登録された前景タスクをまとめて中断します．

`-w`によるタイムアウトはPicoNIX側の`nc`にはありません．Linux側のnetcatとオプションを混同しないでください．

## 確認例

Linux側で`nc -u -l 12345`を起動し，PicoNIX側から上記の`echo hello | nc -u -N ...`を実行します．受信後，PicoNIXのプロンプトに戻ることを確認してください．PC側のIPが`192.168.4.2`であることを確認してください．割り当てが異なる場合は実際のアドレスに置き換えます．LinuxからPicoNIXへ接続する場合の宛先は`192.168.4.1`です．

ファイル・メモリの転送例は[ddガイド](../../literacy/DD.md)を参照してください．
