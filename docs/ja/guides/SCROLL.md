# scroll：selectとUDPによるLED文字スクロール

## 目的

`scroll` は8×8 LEDマトリクスにASCII文字を右から左へ流すユーザプログラムです．標準入力とUDPソケットを`select()`で監視し，受信速度と表示速度を1 KiBのリングバッファで分離します．カーネルに専用サービスを追加しません．

## 実行

```sh
echo HELLO | scroll
scroll -u 2001 &
mcpd &
```

`scroll` は `/dev/gpio/fb` を開き，表示を有効にします．UDPを使うにはPico Wとネットワーク接続が必要です．`-u` は全インターフェースのUDP 2001番で待ち受けます．通常の起動では標準入力だけを読みます．`scroll` の実行中はLED用GPIO 0～15を他のアプリと共有しないでください．

## データの流れ

```text
stdin ─────────────┐
                   ├─ select() ─→ 1024-byte ring ─→ 5×7 font ─→ /dev/gpio/fb
UDP port 2001 ─────┘
MCP client ─→ mcpd (TCP 8080) ─→ UDP 127.0.0.1:2001
```

受信側は空き容量を確認してからデータを追加します．描画側は5×7フォントの左右の空白列を省き，文字ごとに必要な幅だけを描画します．通常の文字間には消灯列をちょうど1列挿入します．点灯LEDの中心間は2ドットピッチになりますが，間の消灯LEDは1個です．空白を省くと文字が接触するため，これが最小の非接触間隔です．スペース文字は単語の区切りとして計2列の空白を挿入します．表示用の8バイトは各行を表し，毎回1列シフトします．ASCII 0x20～0x7eを受理し，改行などの制御文字は標準入力では無視します．UTF-8日本語は対象外です．

## UDPテキスト入力

UDPデータグラムは要求IDなどのヘッダを持たない，単純なASCIIテキストです．表示可能文字（0x20～0x7e）を順番にリングバッファへ追加し，改行などの制御文字は無視します．空きがなくなった場合は，入りきらない文字を破棄します．UDPへの返信は行いません．

```sh
scroll -u 1234 &
echo hello | nc -u 127.0.0.1 1234
```

MCPの`display_message`は1～128バイトのASCIIテキストをUDP 2001番へ送信します．ACKを待ちません．成功は`sendto()`が要求したバイト数を受け取ったことを示すだけで，受信・キュー格納・LED表示の完了を保証しません．この教材版ではJSONのエスケープや引用符を含むテキストを扱えません．MCPから利用するときは`scroll -u 2001 &`を起動してください．

## 観察課題

1. `echo HELLO | scroll`でパイプとEOFを確認します．
2. `scroll -u 1234 &`を起動し，`echo hello | nc -u 127.0.0.1 1234`で表示を試します．
3. `scroll -u 2001 &`と`mcpd &`を起動し，MCPから`display_message`を呼びます．
4. `trace`で`select`，`read`，`recvfrom`，`sendto`，`write`を観察します．
5. 受信が表示より速い場合の文字の破棄と，UDP配送が保証されない理由を考えます．

## 実装上の制限

現行版はイベント発生後に`msleep(100)`，イベントがないときは`select()`の100 msタイムアウトで表示を進めます．したがって厳密な100 ms周期ではなく，受信処理時間などに応じて変動します．実機で周期精度を検証してください．端末から対話入力する場合，TTYがカノニカルモードならEnterまで文字が届きません．終了時にフレームバッファは無効化せず，表示内容を保持します．外部UDPに認証はないため，信頼できる実験ネットワークだけで利用してください．
