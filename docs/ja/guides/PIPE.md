# パイプと標準入出力

*操作ガイド*

PicoNIXのシェルは，`|`を使ってコマンドの標準出力を次のコマンドの標準入力へ接続できます．`grep`は入力から指定した文字列を含む行を選択します．

## 使用例

```sh
cat test.s | grep movs
echo hello | grep hello | cat
cat test.s | grep movs | hexdump
```

2コマンドまたは3コマンドのパイプラインに対応します．4コマンド以上の連結はサポートしません．`grep`は正規表現ではなく，文字列検索用の小さなコマンドです．

## 仕組み

- `pipe(fds)`は読み取り側`fds[0]`と書き込み側`fds[1]`を返します．
- シェルは`dup()`で標準入出力を退避し，`dup2()`で各コマンドのFD 0（stdin）とFD 1（stdout）を接続します．
- 子タスクは起動時にFDを継承します．シェルは不要なFDを閉じ，実行後に標準入出力を復元します．
- 書き込み側がすべて閉じられ，残りのデータもなくなると，読み取りはEOF（0バイト）を返します．読み取り側が存在しない場合の書き込みはエラーになります．
- 空のパイプの読み取り，満杯のパイプへの書き込みは待機します．内部実装には`O_NONBLOCK`を検査して`OS_EAGAIN`を返す分岐がありますが，現行の`fcntl(F_SETFL)`はパイプFDを対象としておらず，公開APIからパイプを非ブロッキングに切り替えることはできません．

## 制約とシェルの制限

シェルではパイプラインと `&`，`<`，`>` を組み合わせられません．これらは単独コマンドで使用してください．


| 項目 | 上限・仕様 |
|---|---|
| 同時に確保できるパイプ | 2本 |
| 各パイプのリングバッファ | 256バイト |
| タスクごとのFD | 16個（0～15） |
| シェルの連結段数 | 最大3コマンド |
| メモリ確保 | 静的領域を使用 |

`read()` / `write()` は部分読み書きになる場合があるため，必要なバイト数を処理するまで戻り値を確認してください．

パイプはバイト列の通信路であり，ファイルとして`/tmp`に保存されません．`|`はシェルが解釈し，通常のコマンド側で展開する必要はありません．

この機能は最小限のUNIX風実装です．一般的なPOSIXシェルの複雑な引用，パイプとリダイレクトの組み合わせ，任意段数のパイプラインなどをすべて再現するものではありません．

## Ctrl+Cとネットワーク連携

前景パイプラインの実行中にCtrl+Cを入力すると，登録された最大3段の前景タスクをカーネルが中断します．POSIXのシグナル配送ではありません．`echo hello | nc -u -N 192.168.4.2 12345`のような単発送信は，[ncの解説](../reference/network/NC.md)を参照してください．

**実装の参照先：** `userland/apps/shell.c` の `run_pipeline()` とコマンド解析，`kernel/kernel.c` の `PIPE_COUNT`，`PIPE_BYTES`，`pipe_transfer()` およびパイプ関連システムコール．
