# B6　選択実習：Pico Wのネットワーク

*Part B — 中級：UNIXを観察する*

**この章の到達目標：** デバイスの次に，通信をソケットとユーザプロセスとして観察する．

> **選択章**：この章は必修ではありません．対応機材がなければ飛ばして構いません．

ここからは**選択学習**です．B5ではピンなどのデバイスにアクセスしましたが，ネットワークでは「別の装置のプログラムとデータを交換する」という新しい問題を扱います．IPアドレスは通信相手の装置，ポート番号はその装置上の通信の入口を識別するための値です．

実習は**Pico Wと，自分で管理するLinux PC**を用い，まずPicoNIX側の状態，次にPCからの接続，最後にパケットの観察へ進めます．コマンドをどちらの機械で打つかを特に注意してください．[ネットワーク接続ガイド](../../reference/network/NETWORK.md)にAP/STAの設定と接続方法があります．

## B6.1 先に機材と安全性を確認する

この章だけは**Pico Wが必須**です．TelnetとHTTPなどは暗号化・認証に制限があるため，インターネットに公開せず，**隔離した実習ネットワークだけ**で試してください．通信実習を省略してもPart Cへ進めます．

## B6.2 Pico W側の状態を調べる

### 通信を3層に分けて観察する

| 対象 | 何を確かめるか | 例 |
|---|---|---|
| Wi-Fi接続 | Pico WがAP/STAのどちらで動いているか | `cat /proc/net/wifi`（PicoNIX側） |
| プロセスとソケット | 誰が通信を受け付けているか | `ps`，`lsof`（PicoNIX側） |
| 通信の中身 | どのようなパケットが行き来するか | `tcpdump -x -c 20`（PicoNIX側） |

`net`や`ip addr`は通信状態を調べる道具であり，`httpd`はHTTPリクエストに応じる**ユーザプログラム**です．`curl`はLinux PCで使うツールで，PicoNIXには用意されていません．接続できなければ，いきなりアプリを改造せず，SSID・Wi-Fi状態・IPアドレス・`httpd`の起動状態の順に確認してください．TCPとUDPの違いやソケットAPIは[ネットワーク開発ガイド](../../development/apps/c/NETWORK-PROGRAMMING.md)で詳しく扱います．

```text
piconix# net
piconix# ip addr
piconix# cat /proc/net/wifi
piconix# ps
piconix# lsof
```

ここは**PicoNIX側**で入力します．AP/STA，IPアドレス，HTTPサーバのプロセスとソケットを分けて観察します．IPアドレスはモードや環境によって変わります．

## B6.3 PCからアクセスする

APに接続した**Linux PC側**の端末で，実機のIPアドレスを確認してから，例えば次を試します．

```sh
curl http://192.168.4.1/
```

これはAPモードの例です．`curl`は**ホストPCのコマンド**で，PicoNIXのコマンドではありません．`httpd`はユーザ空間のサーバ，Telnet（TCP 23）とUDP 2000番のデバイス制御はカーネル側のサービスです．

## B6.4 実習と確認

**つまずいたときの確認順：** (1) Linux PCがPico WのAPへ接続しているか．(2) PicoNIXの`ip addr`でIPを把握したか．(3) `ps`で`httpd`が動いているか．(4) PC側からHTTPを送ったか．(5) PicoNIXで`tcpdump`に受信イベントがあるか．**ポイント：** Wi-Fi接続，TCPサービスの待受，HTTPの応答は別段階です．どこまで成功したかを分けて記録してください．

1. IPアドレスとポートは何を区別しますか．
2. `httpd`とカーネル常駐のTelnetはどこで動くか異なりますか．
3. USBとWi-Fiで端末を使っても，同じOSのプロセス情報を観察できるのはなぜですか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．

### B6追加実習：Telnet，通信状態，ループバック

Pico WのAPモードでは，多くの構成で`192.168.4.1`がPico Wのアドレスで，DHCPによりPCへ`192.168.4.2`が割り当てられます．**実際の値は`ip addr`と`cat /proc/net/wifi`で確認**してください．個体別のSSIDは起動メッセージから確認します．接続先を特定できない場合はここで止めます．

APに接続した**Linux PC側**で次を実行し，Telnet側の`ps`とUSB側の`ps`を比較します．Telnetクライアントは`Ctrl+]`，`quit`で終了できます．

```sh
telnet 192.168.4.1
```

PicoNIX側で`net -r`，`cat /proc/net/memory`を調べると，ARPやネットワークの資源状態を観察できます．ARPに相手が現れないことは，直ちに故障を意味しません．`httpd`が起動していれば，PicoNIX上で`nc 127.0.0.1 80`を使い，同じ装置へのTCP接続も試せます．`GET / HTTP/1.0`に続く空行が必要で，端末の改行設定によっては応答を得られない場合があります．

### B6追加実習：`tcpdump`で通信を見つける

Pico W側のUSB端末で次を実行して待ち受け，別の**Linux PC**から`curl http://192.168.4.1/`を実行します．このIPアドレスはAPモードの例です．

```text
piconix# tcpdump -x -c 20
```

`tcpdump`はPicoNIX自身のIPv4 TCP/UDP/ICMP通信の要約を表示します．`-c N`でN件表示後に終了し，`-x`でデータ長と先頭最大16バイトを16進数・ASCIIで追加表示します．**Linux版と異なり**，他の機器同士の通信やEthernetフレームの取得，pcap保存には対応しません．出力形式の一例（実測値ではありません）：

```text
RX TCP 192.168.4.2:52000 > 192.168.4.1:80 LEN=60 DATA=16 ACK PSH
    DATA:  47 45 54 20 2f 20 48 54 54 50 2f 31 2e 30 0d 0a | GET / HTTP/1.0..|
```

`RX`/`TX`は受信/送信，`LEN`はIPv4パケット全体長，`DATA`はヘッダを除くデータ長です．2行目はデータが存在するときだけ表示されます．`SYN`・`ACK`・`PSH`から接続とデータ送受信の順序を考えてください．記録は16件のリングバッファなので，通信が多いと古い記録が上書きされます．通信が発生しない場合は`Ctrl+C`で終了します．

さらに別のPicoNIX端末から`ping -c 2 192.168.4.1`を実行すれば，ICMP Echo Request（TYPE=8）とEcho Reply（TYPE=0）も比較できます．自分で管理する**隔離された実験ネットワーク**でのみ使用してください．詳しい通信仕様は[ネットワークリファレンス](../../reference/network/NETWORK.md)にまとめています．

**確認：** IPとポート，ユーザ空間の`httpd`とカーネル内Telnet，TCPとICMP，`net`と`tcpdump`がそれぞれ何を観察するか説明してください．
