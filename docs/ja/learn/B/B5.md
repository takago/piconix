# B5　デバイスはファイルに見える

*Part B — 中級：UNIXを観察する*

**この章の到達目標：** デバイスI/Oを通常ファイルと比較し，OSの抽象化を説明する．

B1で学んだVFSは，通常ファイル以外にも共通の名前空間を提供します．B5では，**物理機器（ハードウェア）**と，**OSから見える入口（デバイスファイル）**を区別します．`/dev/gpio/...`のような名前は実際の電子回路そのものではなく，OSが公開する操作方法です．

初めてハードウェアに触れる場合は，まず読むだけの操作に限定します．実際のピン配置と電気的制約は[ハードウェアのピン割当](../../reference/hardware/PINS.md)，デバイスノードの意味は[デバイスリファレンス](../../reference/devices/DEVICES.md)で扱います．両方を混同しないことが重要です．

## B5.1 デバイスを列挙する

```text
piconix# ls /dev
piconix# ls /dev/gpio
piconix# pins
piconix# cat /proc/fb
```

まず読み取りだけで調べます．`/dev`は物理機器などへの操作口，`/proc`は状態を示す仮想ファイルです．ここでは**外付け回路なし**で進められます．

**観察の限界：** `cat /proc/fb`からはフレームバッファの表示データを確認できますが，LEDマトリクスの実配線が正しいことまでは保証しません．機器を動かす実験は**任意**とし，接続済みの回路に限って[デバイスガイド](../../reference/devices/DEVICES.md)の`fbctl`やGPIO・PWM・I²C手順に従ってください．端末への文字出力と実際のピン制御は別の操作です．

## B5.2 read/writeだけで十分か

### 何を見ているのか分類する

| 観察先 | 意味 | 自分で確認すること |
|---|---|---|
| `/dev` | OSが公開するデバイスの入口 | 名前を見て用途を推測し，仕様で確かめる |
| `pins` | ピン割当の情報 | GP番号と利用機能の対応 |
| `/proc/fb` | フレームバッファなどのOS側の状態 | 実物の配線確認とは別だと理解する |
| `reference/hardware/WIRING.md` | 電気的接続の説明 | 実際につなぐ部品・電圧・抵抗の条件 |

**実習の順序：** まず`ls /dev`を実行して結果を記録し，次に`pins`と照合します．外付けLEDを実際に点灯させる操作は，ピンが他の機能に予約されていないことと安全な配線が確認できた場合に限ります．GPIOの値の読み書きはOSの機能，LEDの明るさや点灯は物理回路の現象です．

文字デバイスは通常の`open()`，`read()`，`write()`を使える場合があります．しかしピンの方向や動作モードなど，単純なバイト列では表しにくい操作は`ioctl()`を利用します．OS側ではVFSが要求を機器ごとのドライバへ振り分けます．

## B5.3 実機実験は配線を確認してから

LEDマトリクス，GPIO，PWM，I²C等を操作するときは，先に[ピン割当](../../reference/hardware/PINS.md)・[配線と電気的注意](../../reference/hardware/WIRING.md)と[デバイスガイド](../../reference/devices/DEVICES.md)でピンの専有や電圧を確認します．3.3 Vを超える信号を直接入力しないでください．配線のない環境では，ここまでの読み取り実験だけで修了できます．

## B5.4 実習と確認

**手順を追う実習：** (1) `ls /dev`と`ls /dev/gpio`で名前を観察する．(2) `pins`でGP番号の役割を調べる．(3) `/proc/fb`が示す状態と物理配線を別の表にまとめる．**到達点：** 「どのファイルを開くか」「どのピンに接続するか」「どの関数が制御するか」は三つの別の問いだと説明できれば，部品を実際につながなくても合格です．

`/tmp`に保存した内容と`/proc/fb`の表示を比較します．

1. 同じ`cat`でも情報の出所はどう異なりますか．
2. `/dev`と`/proc`を同じ種類の保存ファイルとみなせますか．
3. デバイスを操作する前に仕様や配線を確認する理由は何ですか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．

### 観察のための最短手順

```text
piconix# ls /dev
piconix# cat /proc/devices
piconix# cat /proc/uptime
```

`/dev`でアプリが開ける装置の名前を，`/proc/devices`で公開ノードの一覧を確認します．`/proc/uptime`のような仮想ファイルは物理配線が不要です．**読むだけの実習**を先に済ませ，GPIOへ書き込む実験は[ピン割当](../../reference/hardware/PINS.md)と[デバイス仕様](../../reference/devices/DEVICES.md)を確認してから行います．将来自分でデバイスを追加する場合は[仮想デバイス演習](../../development/drivers/DRIVER-DEVELOPMENT.md)を利用してください．
