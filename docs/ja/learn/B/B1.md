# B1　FDとVFS：名前をI/Oへつなぐ

*Part B — 中級：UNIXを観察する*

**この章の到達目標：** ファイル・端末・パイプを同じ操作で扱える理由を説明する．

A2で`echo hello | cat`を使うとき，`echo`は送り先の実体を知る必要がありませんでした．その仕掛けを理解する鍵が，**ファイルディスクリプタ（FD）**です．FDはプロセスごとの小さな整数で，開かれた入出力先を参照します．「FD 1が常に画面」なのではなく，「通常は標準出力として使い，シェルが向け先を付け替えられる」と考えてください．

**VFS（仮想ファイルシステム）**はパス名を整理し，通常ファイル・デバイス・状態ファイルなどへのアクセスを共通化する層です．FDとVFSは同義ではありません．FDは開いた後の番号，VFSはパスを解決して操作を渡す仕組み，という二段階に分けます．

## B1.1 FDは何を表すか

ファイルディスクリプタ（FD）は，プロセスが開いているI/O対象を指す**番号**です．一般に0は標準入力，1は標準出力，2は標準エラーとして使われます．コマンドはI/O先の具体的な種類を意識せず`read()`や`write()`を使えます．

## B1.2 観察してつなげる

### FDの対応を紙に描く

```text
単独実行：cat の FD 0 → 端末入力，FD 1 → 端末出力
パイプ：  cat の FD 0 → パイプの読み側，FD 1 → 端末出力
```

これは**概念図**であり，実装のFD表全体を表すものではありません．`lsof`は開かれているFDを調べるコマンドですが，瞬時に終了する`echo`や`cat`のFDを後から追跡できるとは限りません．その場合は異常ではありません．パイプを作る`pipe()`，標準入出力を付け替える`dup2()`，不要な入口を閉じる`close()`については[パイプ操作ガイド](../../guides/PIPE.md)に具体例があります．

次のB2では，FDの先が端末だった場合の入力処理を考えます．

```text
piconix# lsof
piconix# echo hello | cat
piconix# ps
```

`lsof`でFDの割当を確認します．ただし短いコマンドが終了した後は，そのFDが表示されない場合があります．パイプの接続とFDの複製については[補助ガイド](../../guides/PIPE.md)で`pipe()`，`dup2()`，EOFを確認してください．

## B1.3 VFSによる共通操作

VFSはパスを解決して対象ごとの処理へ橋渡しします．`/tmp`の通常ファイル，`/dev`のデバイス，`/proc`の状態表示は同じ保存方式ではありません．しかしプロセスからは**共通の名前空間とI/O API**を通してアクセスできます．

## B1.4 実習と確認

**手順を追う実習：** (1) `echo one | cat`を実行する．(2) 「左のFD 1→パイプ→右のFD 0」の図を書く．(3) `lsof`で現在生きているプロセスのFDを観察する．**よくある誤解：** パイプのFDが`lsof`に見つからなくても，瞬時に終了したプロセスのFDは既に解放されています．「見えない＝パイプを使っていない」ではありません．

`cat /tmp/hello.txt`と`cat /proc/uptime`で，読み取っている情報の性質を比較します（前章でファイルを作っていなければ作成してください）．

1. FD 1は「画面そのもの」でしょうか．
2. パイプは通常ファイルに保存されますか．
3. VFSは何を共通にし，何を個別の実装へ委ねますか．
