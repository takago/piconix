# B2　TTY：入力と画面の境界

*Part B — 中級：UNIXを観察する*

**この章の到達目標：** 端末の入力設定と，アプリケーションの描画を区別する．

B1では「端末もFDを通して操作できる」と学びました．では，入力した文字がすぐにアプリケーションへ届く場合と，Enterまでまとまって渡される場合があるのはなぜでしょうか．その違いを説明するのがTTYの設定です．

ここでは**TTYの入力設定**（行単位の入力，エコーなど）と，**アプリによる画面描画**（カーソル位置，画面の書換え）を区別します．`stty`の変更は入力操作を難しくする場合があるため，まず[TTY設定ガイド](../../guides/TTY.md)と[端末操作ガイド](../../guides/TERMINAL.md)の復旧手順を確認してください．

## B2.1 端末を確認する

```text
piconix# tty
piconix# stty
```

TTYは文字を出し入れする端末の抽象です．USB CDCのコンソールやUART1，Pico WのTelnetなどは，接続方法が異なっても共通のTTY処理を利用します（利用できる端末は機種と構成によります）．

## B2.2 行入力と一文字入力

### 三つの設定を混ぜない

| 項目 | 影響するもの | 例 |
|---|---|---|
| canonical入力 | Enterまで行をまとめるか | `stty icanon` / `stty -icanon` |
| echo | 入力した文字を端末へ表示するか | `stty echo` / `stty -echo` |
| `O_NONBLOCK` | データ待ちで`read()`が待機するか | Cアプリの`fcntl()`で設定 |

PicoNIXの`stty raw`は行入力とエコーを同時に無効化する**簡易指定**です．Linuxの完全なrawモードとは異なります．端末の設定を変更した後で文字が見えなくなっても，直ちにOSの故障とは限りません．設定を戻す操作は[TTY設定ガイド](../../guides/TTY.md)に従い，無理にキーを連打しないでください．

次のB3では，こうしたプログラムの状態や実行領域を，RAMの視点から観察します．

`stty`はcanonical（行単位）とecho（入力文字の表示）などを扱います．`stty raw`はこれらを簡略的に無効化し，`stty cooked`で戻せますが，通常のPOSIX rawと完全に同じではありません．最初は表示の観察だけを行い，切替は[TTY設定](../../guides/TTY.md)を確認してから試してください．

**追加実習（端末が元に戻せる環境でのみ）：**

```text
piconix# stty
piconix# stty raw
piconix# stty
piconix# stty cooked
piconix# stty
```

`raw`はPicoNIXの簡易設定で，canonical入力とエコーを切り替えます．POSIXの`termios`でいう完全なrawモードとは異なります．表示・入力が不便になった場合に復旧できるよう，[端末操作ガイド](../../guides/TERMINAL.md)を先に読んでください．通常の状態に戻すには`stty cooked`を使用します．

## B2.3 入力を管理する側と画面を描く側

TTYの入力状態や改行変換はカーネル側が担い，`edit`・`vi`・`mem`などの全画面表示はアプリケーション側の責任です．FDごとの非ブロッキング設定は`fcntl()`，TTYの設定は`ioctl()`のように，制御対象によってAPIが違うことを確認します．

## B2.4 実習と確認

**安全な確認：** 初めは`tty`と`stty`の出力だけを書き取り，`icanon`，`echo`などの名前を確認します．変更実習を行うときは，別の端末で復旧できるか確かめたうえで切り替えます．**観察の焦点：** 行編集は端末入力側の処理ですが，`mem`の画面を周期的に描き直すのはアプリ側の処理です．二つの責任の境界を言葉で説明してください．

`tty`と`stty`の結果を記録します．

1. 行入力と入力文字のエコーは同じ設定ですか．
2. TTY設定と画面カーソルの移動はどちらが管理しますか．
3. `O_NONBLOCK`とcanonical入力を同一視できない理由は何ですか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．
