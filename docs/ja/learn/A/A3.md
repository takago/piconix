# A3　プログラムとプロセス

*Part A — 初級：UNIXを使う*

**この章の到達目標：** 登録されているプログラムと，実際に動いているプロセスを区別する．

A2ではデータの流れに注目しました．次は，そのデータを処理する**プログラムがいつ動いているのか**を考えます．`/bin`に存在する実行イメージと，実際にCPUの実行機会を与えられているプロセスは同じではありません．`ps`の結果は時点ごとの写真のようなものです．

**用語：** プログラムは実行可能な命令などのまとまり，プロセス（PicoNIXの表示ではタスク）はそれを実行中の単位，PIDはその識別番号です．RAMスロット番号とPIDは別です．背景実行を試す前に，停止操作を`help kill`で確認してください．

## A3.1 プログラムはまだ実行中とは限らない

`ls /bin`は**起動できるコマンド**を示します．`ps`は**その時点で動いているタスク**を表示します．同じコマンドを複数回起動すると，プログラム名は同じでもPIDは異なります．

## A3.2 背景で動かす

### どうして背景実行で確認できるのか

`blink &`を起動したあと，シェルは次のコマンドを受け付けます．一方，`blink`も動き続けます．つまり，端末の入力を待つシェルと別の仕事が共存できています．ただし**同時にCPUコア上で走っている**という意味ではなく，OSが実行機会を切り替えていることを示します．

観察記録には，起動**前**の`ps`，起動**後**の`ps`，`kill`による停止**後**の`ps`を並べてください．`kill`の引数には画面に表示されたPIDを使い，例示の文字列`PID`をそのまま入力しないでください．意図せず別タスクを止めないよう，表示名と番号を照合します．

```text
piconix# ps
piconix# blink &
piconix# ps
piconix# cat /proc/tasks
```

`&`はシェルに背景実行を指示します．観察したら`ps`で表示された実際のPIDを確認し，`kill PID`の`PID`部分をその数字に置き換えて停止します．**固定のタスクスロットは有限**なので，背景プロセスを放置しないでください．

## A3.3 OSによる資源管理

プロセスは自分のプログラムを実行しますが，実行機会やRAMスロットはOSが管理します．背景で`blink`が動いていてもシェルが入力を受け付けられることは，単一のCPU上でも複数の仕事を切り替えられることを示しています．

**注意：** `kill PID`は例示表記です．実際には`ps`で得た番号を指定します．`ps`と`cat /proc/tasks`の結果を比較し，実行中のプロセス名・PID・状態の対応を確認してください．タスクを大量に起動すると，固定スロットが不足し新しいプログラムを起動できなくなります．

## A3.4 実習と確認

**手順を追う実習：** (1) `ls /bin`で`blink`を探す．(2) `ps`を記録する．(3) `blink &`で背景起動する．(4) `ps`から新しいPIDを調べる．(5) `kill`でそのPIDを停止する．**確認すべき結果：** `/bin`の登録プログラム一覧は変わらなくても，実行中プロセスの一覧は増減します．実行できることと実行中であることは別です．

`ps`を実行する前後で，表示内容がどのように変化するか記録します．

1. プログラム名・PID・タスクスロットは同じものですか．
2. `&`なしで実行した場合と何が異なりますか．
3. `kill`で止める対象はどの値で指定しますか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．
