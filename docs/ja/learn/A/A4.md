## A4.1 観察の手順を組み立てる

次の4段階を**自分で**再実行します．(1) `ls /bin`からプログラムを見つける，(2) `echo`でRAMファイルを作る，(3) `|`で別のコマンドへ渡す，(4) `ps`で実行中の状態を調べる．各操作が「ファイル」「入出力」「プロセス」のどれを扱うか注記してください．

## A4.2 試したことを記録する

### 観察ノートの書き方

| 項目 | 記録する内容の例 |
|---|---|
| 目的 | `hello`を保存して読み戻したい |
| 予想 | `>`で作った`/tmp`のファイルはコマンド終了後にも読める |
| 操作 | `echo hello > /tmp/hello.txt`，続けて`cat /tmp/hello.txt` |
| 観察 | 出力された文字列と，作成されたファイル名 |
| 説明 | シェルが出力先をファイルへ変更したため |

**中級への橋渡し：** ここまでは「なぜ`cat`は画面とファイルの両方に読み書きできるのか」をまだ十分に説明していません．Part BではFDとVFSを手がかりに，その仕組みを確かめます．

```text
piconix# echo lesson > /tmp/lesson.txt
piconix# cat /tmp/lesson.txt
piconix# echo lesson | cat -n
piconix# ps
```

画面に出た結果を丸写しするのではなく，「コマンド→観察→説明」の3項目をノートに書きます．PIDや出力の順序は実行環境で変わります．

## A4.3 UNIXの三つの見方

ここまでに，**(1) 名前で資源を探す，(2) 入出力をつなぐ，(3) 実行単位を管理する**という三つの見方を学びました．次のPart Bでは，これをFD・TTY・システムコール・メモリへ分解して，OSの内部側から説明します．

## A4.4 到達確認

**課題の組み立て方：** 最初に「ファイルを作り，その内容が後から読めることを示す」という予想を書きます．次に`echo`で保存し，`cat`で確認して，その後パイプ版を試します．最後に**同じ表示を得る複数の経路がある**ことを図にしてください．結果が予想と違ったら入力した文字，コマンドの実行場所，ファイル名を順に見直します．

1. `>`と`|`の違いを口頭で説明できる．
2. `/tmp`と`/proc`が異なる種類の場所であると説明できる．
3. `ps`で実行中のタスクを確認し，安全に終了できる．

全て説明できたらPart Bへ進みます．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．
