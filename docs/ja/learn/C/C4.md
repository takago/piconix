# C4　ドライバ：VFSから機器へ

*Part C — 上級：UNIXを読んで改造する*

**この章の到達目標：** カーネル内部のデバイス境界を理解する．

C3ではFDからI/Oの実体へ進む道筋を追いました．ここではその先が**電子回路や周辺機器**だった場合を扱います．「ハードウェアの配線」「OSが公開するデバイスファイル」「ドライバの内部実装」は異なる層です．同じ名前に見えても，それぞれ参照すべき文書が異なります．

## C4.1 デバイスの前にVFS

`kernel/kernel.c`でパスの判定とFD管理を探します．次に`kernel/gpio.c`，`kernel/fb.c`，`kernel/adc.c`，`kernel/pwm.c`などの実装へ移り，どの処理をVFSが担当し，何をデバイス固有の実装へ委ねるかを整理してください．

## C4.2 read/write/ioctl

### 読解対象を一つに絞る

例えばGPIOを選ぶ場合は，`/dev/gpio/N`というパスが何を表すかを仕様書で確認し，`kernel/kernel.c`のパス解決・FD処理から`kernel/gpio.c`の処理へ進みます．次の4つを別々の行にメモします．

| 問い | 調べる層 |
|---|---|
| どの名前で開けるか | VFS・デバイスノード |
| `read`/`write`で何を渡すか | 公開APIとデータ形式 |
| ピンの方向などをどう指定するか | `ioctl()`などの制御 |
| 実際にどのGP番号へ出力するか | ドライバとピン割当 |

回路を接続する前に，GP番号がUART・PWM・I²Cなどに予約されていないかを[ピン割当](../../reference/hardware/PINS.md)で確認します．ドライバのコード読解自体に外付け機材は必要ありません．

デバイスを通常ファイルと似たAPIで操作できる一方，方向設定・モード選択などの専用操作は`ioctl()`が必要です．`/proc`に現れる状態は，通常の不揮発ファイルと同じではありません．**デバイスとネットワークは別の段階**として扱います．

## C4.3 変更する前の確認

[ドライバ開発ガイド](../../development/drivers/DRIVER-DEVELOPMENT.md)で，IDやパスの衝突，pin予約，FDの解放，異常時の戻り値を確認します．この章は**読むことが必修**で，実機配線やコード変更は任意です．

## C4.4 読解課題

**読解演習：** 一つのデバイスを選び，公開パス→VFS上の識別→ドライバの入口→ピンまたは状態という4段階で関数を探します．**検証項目：** 不正なパス，読み書き不可の操作，予約ピンの扱いを確認します．必ずしも実際に回路を接続する必要はありません．デバイスを「使う」資料とドライバを「実装する」資料を区別して参照してください．

一つのデバイスについて，パス名→FD→VFS→デバイス処理の図を作ります．

1. `ioctl()`はどんな用途に向いていますか．
2. 通常ファイルとデバイスノードの違いは何ですか．
3. ドライバの変更時に確認すべき安全条件は何ですか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．
