# C3　SVC・FD・VFSをコードで追う

*Part C — 上級：UNIXを読んで改造する*

**この章の到達目標：** write()が標準出力へ到達する経路を追跡する．

B4の`trace run hello`では`write()`などのシステムコールを観察しました．この章では記録に出てきた`write`が，**どのソースコードを通って端末出力へ届くのか**を追います．C関数の呼び出しとSVC例外とを区別して読み，実行時の観察をソースの根拠で説明できるようにします．

最初に[システムコール一覧](../../reference/SYSCALLS.md)で`write`の引数と戻り値を確認し，実行時の観察方法は[trace操作ガイド](../../guides/TRACE.md)に戻って確認してください．FDとVFSの仕組みはB1と[ファイルシステム仕様](../../reference/FILESYSTEM.md)で復習できます．

## C3.1 ユーザからSVCへ

`userland/apps/hello.c` → `userland/lib/syscalls.c`の`write()` → `call()` → `include/piconix_syscall.h` → `kernel/context.S`のSVCハンドラ → `kernel/kernel.c`の`os_svc_dispatch()`の順に読みます．公開APIとABIの番号，SVCと通常の関数呼び出しを混同しないでください．

## C3.2 カーネルからI/O対象へ

### 一つの`write`だけを追う

```text
hello.c の表示要求
  → userland/lib/syscalls.c
  → SVC（システムコールの境界）
  → kernel/kernel.c のディスパッチ
  → FDが示す対象の書き込み処理
  → 呼び出し元へ戻り値
```

これは**読解の道筋**であり，すべての内部関数を列挙した図ではありません．各矢印で「この関数が次の処理をどう呼ぶか」を確認してください．`write()`が成功したときの戻り値は一般に書き込んだバイト数で，文字列の長さと必ずしも同じとは限りません．失敗や部分書き込みの可能性もあります．

`echo hello | cat`では，シェルがパイプを作り，子プロセスにFDを渡します．パイプの読み手がEOFを受け取る条件は，**書き込み側FDがすべて閉じられ，残りのデータもなくなること**です．詳しくは[パイプガイド](../../guides/PIPE.md)で確認します．

`SYS_WRITE`の分岐を探し，FDが指す対象とVFS側の読み書き実装をたどります．端末へ書く場合，ファイルへ書く場合，パイプへ書く場合で**入口は似ていても出口が異なる**ことを確認します．

## C3.3 パイプと待ち合わせ

`userland/apps/shell.c`のパイプライン構築，`pipe()`，`dup2()`，`close()`，EOFを追います．データがないときの待機と，終端で読み手が終了する条件を分けて説明します．初めから全ての例外分岐を読むより，`echo hello | cat`の1回の動作を追うと理解しやすくなります．

## C3.4 読解課題

**読解演習：** B4で得た`write`イベントを一つ選びます．`SYS_WRITE`の定義，SVCの入口，`os_svc_dispatch()`，対象FDの分岐をソースで追います．**提出する図：** 各段階のファイル名と関数名を記入した呼び出し経路です．**注意：** 通常ファイル，TTY，パイプではFDの先が異なります．最初は標準出力一つに絞ってください．

PicoNIXで`trace run hello`を再実行し，ソースの関数と出力を対応付けます．

1. 呼び出し番号はどこで定義されますか．
2. FDの対象によって分岐するのはどの層ですか．
3. パイプのEOFはどのような条件で起こりますか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．

### 追加実習：新しいSVCを通す

ユーザAPI→`call()`→`svc #0`→`os_svc_dispatch()`の順で既存の`getpid()`を探したら，[システムコール追加実習](../../development/syscalls/SYSCALL-DEVELOPMENT.md)へ進みます．**番号40の`getuptime()`**を追加する手順，動作確認用Cアプリの登録方法，演習専用のソースパッチまで用意しています．`trace run labuptime`でSVCを確認し，「なぜ共有番号表が必要か」を説明してください．
