# C5　選択読解：Pico Wネットワーク

*Part C — 上級：UNIXを読んで改造する*

**この章の到達目標：** デバイスI/Oとは別に，lwIPとソケットの経路を読む．

> **選択章**：この章は必修ではありません．対応機材がなければ飛ばして構いません．

これは**Pico W向けの選択読解**です．B6の通信実習を済ませていると理解しやすくなりますが，通常のPicoで学ぶ場合はC6へ進めます．ここではデバイスドライバの続きとして扱うのではなく，Wi-Fi制御とTCP/IPスタック，アプリからのソケット利用という**別の経路**を追います．

ネットワークの基盤を扱う`kernel/net.c`と，ユーザプロセスのソケット要求を扱う`kernel/net_socket.c`を区別します．読む順序と注意点は[カーネル側ネットワーク開発ガイド](../../development/network/NETWORK-DEVELOPMENT.md)を基準にしてください．

## C5.1 この章の位置づけ

**Pico W限定の選択章**です．Part Bのデバイスとネットワークの違いを理解してから進みます．通常のPicoや通信を扱わない授業はこの章を飛ばし，C6へ進めます．

## C5.2 二つの経路を見る

### HTTPとTelnetの違いを実装で説明する

| 観点 | HTTP | Telnet |
|---|---|---|
| 実装場所 | `userland/apps/httpd.c` | `kernel/net_service_telnet.c` |
| 実行主体 | ユーザプロセス | カーネル常駐サービス |
| 確認ポイント | 起動・終了・ソケットFD | カーネル内での接続処理 |

「同じTCPを使うのに実装場所が違うのはなぜか」を説明できることが学習目標です．UDP 2000番のリモートデバイス制御はさらに別のカーネルサービスです．ソケットの呼び出し手順を理解するには[ユーザアプリ向けネットワーク開発ガイド](../../development/apps/c/NETWORK-PROGRAMMING.md)を使い，通信状態や接続例は[ネットワーク仕様](../../reference/network/NETWORK.md)で確認します．

`kernel/net.c`でWi-FiとlwIPの初期化・管理を，`kernel/net_socket.c`でユーザプログラムのソケットを読みます．`userland/apps/httpd.c`の`socket()`，`bind()`，`listen()`などからSVCへ至る経路を追い，ポートを待ち受ける状態を考えます．

## C5.3 カーネル常駐とユーザサービス

Telnet（TCP 23）とリモートデバイス制御（UDP 2000）はカーネルのサービス，HTTP（TCP 80）はユーザプロセスの`httpd`です．**両者の設計上の違い**を，メモリ配置・終了・再起動・FD管理の観点から整理します．未認証・平文サービスは隔離した実験環境でのみ使用してください．

## C5.4 読解課題

**読解演習：** `httpd`のソケットを開く処理を起点に，ユーザAPI→カーネルのソケット処理→lwIPの流れを図にします．次にTelnetの常駐サービスがどこで接続を受けるかを探します．**比較課題：** サーバの終了や再起動を誰が制御するかを，HTTPとTelnetで分けて説明します．

1. `kernel/net.c`と`kernel/net_socket.c`は何を分担しますか．
2. ユーザの`httpd`とカーネルのTelnetは何が異なりますか．
3. ネットワーク処理がアイドルタスクと関係するのはなぜですか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．

### 追加実習：自作の通信プログラムでSVCを見る

[ユーザCソケットプログラミング](../../development/apps/c/NETWORK-PROGRAMMING.md)で`udp_once`か`tcp_get`を登録し，Pico WからLinux PCへ送信します．`kernel/net_socket.c`の送受信処理と，`userland/lib/syscalls.c`のラッパーを照合し，アプリの通信がカーネルのlwIPへ達する経路を図にしてください．診断には[`ip`](../../reference/network/IP.md)・[`tcpdump`](../../reference/network/TCPDUMP.md)も利用します．
