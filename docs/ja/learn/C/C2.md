# C2　起動，タスク，スケジューラ

*Part C — 上級：UNIXを読んで改造する*

**この章の到達目標：** ユーザコードが動き始めるまでのカーネル経路をたどる．

ユーザプログラムが書けても，それだけでは「どうやって最初の`sh`が動くのか」を説明できません．この章では**起動時の準備**，**プログラムの登録**，**タスクの生成**，**実行の切替**を混ぜずに追います．最初に[カーネル読解ガイド](../../development/kernel/KERNEL-READING-GUIDE.md)の起動とスケジューラの節を開いてください．

関数を読む順序は「呼び出し元→呼び出し先」です．全ソースを1行目から読むのではなく，`kernel/main.c`の`main()`から始め，`register_image()`が実行イメージの**登録**であり，`os_start_program()`が実際の**起動**に関わることを区別します．

## C2.1 mainから最初のシェルへ

`kernel/main.c`の`main()`を開き，`os_init()` → `register_image()` → `net_init()` → `os_init_idle()` → `os_start_program(2)` → `os_start()`の順で追います．**登録**と**実行**が別の操作であることを図示してください．

## C2.2 タスクの準備と切替

### ソース読解の途中結果を残す

```text
初期化 → アプリの登録 → 最初のタスクの準備 → スケジューラ開始
                         ↓
                RAMスロットと初期スタックを設定
```

この図は学習用の概念図です．実際の関数名と分岐は[カーネル読解ガイド](../../development/kernel/KERNEL-READING-GUIDE.md)とソースで確認してください．

**読解のポイント：** SysTickは定期的な割込みを発生させる仕組み，スケジューラは次に実行するタスクを決める処理，PendSVは文脈切替に用いる例外です．三者をすべて「タスク切替」と呼ぶと役割が見えなくなります．`ps`でタスクを観察し，B3の`mem`でスロットを確認した経験と結び付けてください．

次に`kernel/kernel.c`の`spawn_in_slot()`，`os_start_program()`，`os_schedule()`，SysTick関連の処理を探します．`kernel/context.S`のPendSVと組み合わせて，スケジューラが次のタスクを選び，CPUの実行文脈を切り替える関係を読みます．

## C2.3 RAMスロットとレジスタ

固定スロット，初期スタック，保存レジスタとPSPを結び付けます．数値を暗記するのではなく，実際の定数は`include/piconix.h`，関数や定義の位置は[関数一覧](../../../FUNCTIONS.md)で調べます．PicoNIXはLinuxの仮想記憶やプロセス隔離を再現するものではありません．

## C2.4 読解課題

**読解演習：** `kernel/main.c`の呼び出し列に番号を振り，登録処理と起動処理を色分けします．その後，`kernel/kernel.c`で実行タスクを選ぶ関数，`kernel/context.S`で文脈を保存・復元する経路を見つけます．**提出する図：** 「登録されたイメージ→RAMスロット→実行タスク→切替」という流れを関数名つきで示します．

**「起動から最初の`sh`へ」**を5〜10個の関数で矢印図にしてください．

1. アプリ登録時と起動時で何が違いますか．
2. SysTickとPendSVが担当する役割は何ですか．
3. アイドルタスクはなぜ必要ですか．

学習の記録：**実行したこと／結果／その理由**を1〜3文ずつ書いてください．
