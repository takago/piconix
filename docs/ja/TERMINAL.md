# PicoNIX 端末制御の実装・デバッグノート

この文書は，PicoNIXでシェルや全画面アプリ（`mb`，`gpio`，`pong`，`fbed`，`edit`，`mem` など）を開発するときの注意点をまとめたものです．2026年10月に，gtktermとVS Codeの端末で起きた表示・スクロールバックの不具合をもとにしています．

## 1．まず区別するもの

- **PicoNIXのTTY設定**：canonical／noncanonical入力，エコーバック，ONLCR，ブロッキング動作など．`ioctl()` や `fcntl()` が扱います．
- **端末エミュレータの表示状態**：カーソル表示，文字属性，代替画面，スクロール領域，スクロールバックなど．主にANSI／DECエスケープシーケンスで変更します．

TTY設定を元に戻しても，端末エミュレータの表示状態まで自動的に戻るわけではありません．両者は別に扱います．

## 2．改行とカーソル移動

| 出力 | 主な意味 |
| --- | --- |
| `\r`（CR） | 現在行の先頭へ戻る |
| `\n`（LF） | 次の行へ進む |
| `\r\n` | 次の行の先頭へ進む |

ONLCRが有効なTTYでは，通常 `\n` を `\r\n` に変換します．ONLCRの不具合と，端末エミュレータが保存済みのカーソル位置へ復帰する問題は区別してください．

**実例：** シェルがプロンプト表示のたびに `ESC[?1049l` を出していたとき，Enterを押しても同じ行に戻るように見えました．単純なCR／LFの問題ではなく，代替画面解除に伴うカーソル位置復元が関係していたと考えられます．

## 3．よく使うエスケープシーケンス

以下の `ESC` はC文字列では `\033` と記述します．

| シーケンス | 作用 |
| --- | --- |
| `ESC[?1049h` | 代替画面へ切り替える（多くの端末でカーソル位置も保存） |
| `ESC[?1049l` | 通常画面へ戻る（保存したカーソル位置を復元する場合がある） |
| `ESC[?25l` / `ESC[?25h` | カーソル非表示／表示 |
| `ESC[0m` | 色・文字属性を初期化 |
| `ESC[2J` | 表示画面を消去 |
| `ESC[H` | カーソルをホーム位置へ移動 |
| `ESC[r` | スクロール領域を初期化 |
| `ESC[?1007l` | Alternate Scrollモードを無効化（対応端末のみ） |

代替画面は全画面アプリに便利ですが，通常画面と同じスクロールバックを提供しない端末が多くあります．また，代替画面中のマウスホイールを上下カーソルキー入力へ変換する端末もあります．これは `?1007` や端末固有の実装に関係します．

**重要：** `ESC[?1049l` を通常のプロンプト表示のたびに送ってはいけません．代替画面を使っていない状態でもカーソル位置が意図せず復元され，改行・表示位置が乱れる可能性があります．

## 4．全画面アプリの開始と終了

全画面アプリでは，通常，起動時に代替画面へ切り替えてカーソルを隠し，正常終了時に逆の操作をします．以下は概念例です．

```c
/* Enter a full-screen interface. */
printf("\033[?1049h\033[?25l");

/* ... interactive UI ... */

/* Restore the normal screen before returning. */
printf("\033[?25h\033[?1049l");
```

TTYのcanonical／echo設定も変更した場合は，アプリ自身の正常終了時の処理だけに依存しない設計が必要です．Ctrl+Cによる強制終了では，アプリの後始末コードが実行されない場合があります．

### PicoNIXの現行方針（2026年10月30日時点）

- 通常のシェルプロンプトでは `ESC[0m` と `ESC[?25h` を使い，**`ESC[?1049l` は送らない**．
- `shell.c` は，`mb`，`gpio`，`pong`，`fbed`，`edit`，`mem` のフォアグラウンド実行後に `ESC[?1049l` を送る．これにより，正常終了だけでなくCtrl+C中断後にも復帰を試みる．
- TTY設定の復元と，端末エミュレータの画面状態の復帰は，別の処理として考える．
- `reset` はTTY入力設定に加え，代替画面解除，Alternate Scroll無効化，スクロール領域・文字属性・カーソル表示の初期化などを行う．

対象コマンド名をシェル側で列挙する方式には保守上の制約があります．新しい全画面アプリを追加した場合は復帰処理の対象も見直してください．将来的には明示的な画面モード管理も検討できますが，まずは仕組みを単純に保つ方針です．

## 5．実際に発生した症状と調査結果

| 症状 | 調査・対応の要点 |
| --- | --- |
| Enter後も同じ行にプロンプトが現れる | シェルのプロンプト表示から無条件の `ESC[?1049l` を削除して改善した |
| 全画面アプリ終了後もカーソルが隠れる | シェル復帰時に `ESC[?25h` を送ることが有効だった |
| ホイール操作が上下カーソルキーになる | 代替画面またはAlternate Scroll関連の状態を疑う．画面復帰後に改善した |
| ホイールは上下キーにならないが履歴がスクロールできない | `echo -ne '\033[?1049l'` で通常画面へ復帰し，スクロールバックが使えるようになった |
| ソースを直しても実機で変化しない | ZIP展開時の更新日時と増分ビルドの判定を確認する |

最終的にgtktermとVS Codeの端末の両方で問題の解消を確認しました．ただし，Alternate Scroll無効化（`?1007l`）単独の必要性までは切り分けていません．

## 6．PicoNIXからの確認方法

`echo -e` はエスケープ文字を解釈し，`-n` は末尾の改行を省略します．表示状態を調査するときに便利です．

```sh
# 通常画面へ戻る
 echo -ne '\033[?1049l'

# カーソルを表示する
 echo -ne '\033[?25h'

# Alternate Scrollを無効化する（対応端末のみ）
 echo -ne '\033[?1007l'

# 改行の確認
 echo -e 'ABC\nDEF'

# まとめて画面状態を初期化したいときは
 reset
```

上記コードブロックの行頭の空白は説明用です．実機ではプロンプトの後にコマンドを入力してください．画面を消去するシーケンスは診断中の表示履歴を失わせることがあるため，まず個別のシーケンスで切り分けると安全です．

### 確認チェック

1. 起動直後に連続してコマンドを実行しても，プロンプトが次の行へ進む．
2. `mb`，`gpio` などの正常終了後に，カーソルが表示される．
3. 同じアプリをCtrl+Cで中断しても，シェルが操作できる．
4. マウスホイールが上下キー入力にならない．
5. **通常画面で新たに出力した長い結果**を，ホイールでさかのぼれる（代替画面内の内容は保存されないことがある）．
6. gtktermとVS Codeなど複数の端末で確認する．

## 7．ビルド結果が反映されない場合

増分ビルドでは，ソースと成果物の更新日時によって再コンパイルが判断されることがあります．ZIPからソースを展開したとき，古い更新日時が復元されると，変更を取りこぼす可能性があります．

```sh
unzip -o PicoNIX-patch.zip
touch userland/shell.c userland/reset.c
# 通常のビルドコマンドを実行する
```

`touch` するのは実際に更新したファイルです．それでも反映されない場合に，対象ビルド成果物や `build` ディレクトリの削除を検討します．何よりも，**検証中のUF2に修正版が入っていること**を確認してください．

## 8．新しい全画面アプリを実装するときの原則

- 代替画面への切替えと復帰は対応させる．
- カーソルを隠したら，終了時に表示を復元する．
- TTY入力モードと端末画面モードを混同しない．
- 正常終了だけでなく，Ctrl+C等の強制終了も想定する．
- シェルの通常プロンプトで画面モード復帰を無条件に繰り返さない．
- 終了後はカーソル・ホイール・スクロールバックを**別々に**確認する．
