# カーネル読解演習

[カーネル読解ガイド](../development/kernel/KERNEL-READING-GUIDE.md)の段階に沿った確認問題です．まずコードを変更せずに各関数を追ってください．

## 確認問題

1. 登録と起動は何が違うか．なぜアイドルタスクが必要か．
2. プログラムID・PID・スロット番号は同じか．RAMスロットはいつ確保されるか．
3. SysTickとPendSVは何を分担しているか．実行可能なユーザタスクがない場合どうなるか．
4. タスクを切り替えたあとに，別のタスクの続きから実行できるのはなぜか．SVCとPendSVは目的がどう違うか．
5. ユーザコードが直接デバイスを操作する代わりにSVCを使う理由は何か．
6. 同じ`read()`が通常ファイルとデバイスの双方で動くのはなぜか．EOFはどのように表すか．
7. パイプの読取側がデータを待つときタスクはどうなるか．書込側の参照がなくなったことをどこで判断し，EOFを返すか．TTYの入力行編集と画面制御は誰の責任か．
8. デバイス固有のコードを通常のI/O入口から切り離す利点は何か．VFS側とドライバ側では何を担当するか．
9. `net_poll()`はなぜ必要か．`httpd`がユーザプログラムなのに，Telnetサービスはカーネル側にあるのはどのような設計上の違いか．
10. `spawn_in_slot()`で作られる初期フレームの順序と`isr_pendsv`の復元順序を照合する．続いて`device_rw_tty()` → `os_schedule()` → `wake_readers()` → `task_unblock()`を追い，なぜ`wait_frame_ready`と`t->sp[8]`が必要なのか説明する．最後に`SYS_SLEEP`と`SYS_YIELD`の違いを説明する．

## 最終演習：一つの操作を端から端まで追う

`trace run hello`を実行したうえで，**「シェルがhelloを起動し，文字列がTTYへ出力され，終了するまで」**を次の順に説明してください．

11. シェルの起動要求（`spawn()`）とSVC
12. 実行イメージの読み込み・タスクの準備
13. スケジューラとPendSVによる最初の実行
14. `write()`からVFSとTTYへの経路
15. 終了処理，FDの解放，スロットの再利用

余力があれば，`echo hello | cat`の起動・FD複製・ブロック・EOFまで同じ方法で図示します．**コードの変更が目的ではなく，関数間の関係を説明できることが到達目標です．**
