# Filesystem and device nodes

[日本語](../ja/FILESYSTEM.md) | [Documentation index](DOCS.md) | [Device operations](DEVICES.md)

PicoNIX provides a small virtual filesystem (VFS). **Directories and device nodes are generated by the kernel; they are not ordinary files on a disk.** Regular files under `/tmp` and `/etc` are held in SRAM and disappear on reboot. This reference is based on the VFS registration and enumeration code in `kernel/kernel.c` and the pin configuration in `kernel/pins.h`.

## 1. Directory layout

```text
/
├── bin/                    Built-in user programs
├── dev/                    Devices
│   ├── console             Main terminal
│   ├── ttyS1               UART1 terminal
│   ├── ttyN0               Wi-Fi terminal (Wi-Fi builds only)
│   ├── net/
│   │   └── wifi            STA reconnection control (Wi-Fi builds only)
│   ├── rand                Simple pseudorandom generator
│   ├── mem                 Read/write permitted memory regions
│   ├── shm                 Shared 2-KiB RAM
│   ├── trace               Binary trace events
│   ├── gpio/
│   │   ├── fb              8×8 LED framebuffer
│   │   ├── N               GPIO value
│   │   ├── N.dir           GPIO direction
│   │   └── N.pull          Pull-up/pull-down setting
│   ├── i2c/
│   │   └── 1               I²C1 bus
│   ├── adc/
│   │   ├── 0, 1, 2         ADC inputs (configuration-dependent)
│   │   └── temp            Internal temperature sensor
│   └── pwm/
│       └── 1/              Present when PWM is configured
│           ├── freq        Frequency
│           ├── a           GP18 duty cycle
│           └── b           GP19 duty cycle
├── proc/                   System status
│   ├── uptime, ticks, interrupts, context_switches
│   ├── memory, devices, ramfiles, tasks, fb
│   ├── task/PID            Status of a running task
│   ├── sym/
│   │   ├── kernel          Kernel symbols
│   │   └── userland/NAME   Symbols for a registered program
│   └── net/
│       ├── wifi            Wi-Fi/DHCP and STA/AP status
│       ├── ap              Associated AP clients
│       ├── arp             ARP cache
│       └── memory          lwIP heap, pbufs and idle stack
├── tmp/                    Volatile RAM files
└── etc/                    Volatile configuration files
    ├── rc                  Startup script
    ├── index.html          Pico W landing page
    ├── fbcheck.html        Pico W LED controls
    └── pwm.html            Pico W PWM controls
```

`N`, `PID`, and `NAME` are placeholders, not literal filenames. `/bin` lists registered built-in programs. `/proc/task` enumerates **active PIDs**. Files under `/proc/sym/userland/NAME` can be opened directly by program name, but the current directory enumeration does not list children of `/proc/sym/userland`. `/dev/pwm/1` is available only when PWM is configured. The HTML files are part of the Pico W initial file set, not the plain Pico default. `/proc/net/memory` can also be read on plain Pico but reports only `MODE: N/A` and `IDLE_STACK` (no lwIP stack).

## 2. Node types and access

| Node | Read | Write | Notes |
|---|:---:|:---:|---|
| `/dev/console`, `/dev/ttyS1`, `/dev/ttyN0` | Yes | Yes | Terminals; `/dev/ttyN0` only in Wi-Fi builds |
| `/dev/rand` | Yes | No | Non-cryptographic PRNG; at most 4 bytes per read |
| `/dev/mem` | Yes | Restricted | Read permitted XIP flash/SRAM; writes are limited to task slots, SHM and RAM-file payloads; absolute `lseek()` address |
| `/dev/shm` | Yes | Yes | Shared 2-KiB RAM, indexed from offset zero |
| `/dev/trace` | Yes | No | Binary records; see the `trace` command |
| `/dev/gpio/fb` | Yes | Yes | Exactly 8 bytes; enable using `ioctl()` |
| `/dev/gpio/N`, `N.dir`, `N.pull` | Yes | Yes | Only pins configured as GPIO in `pins.h` |
| `/dev/i2c/1` | Yes | Yes | I²C1 bus; transfers use `ioctl()`. See [I²C guide](I2C.md) |
| `/dev/adc/0`–`2`, `/dev/adc/temp` | Yes | No | Decimal text; 0–2 depend on ADC pin configuration |
| `/dev/pwm/1/freq`, `a`, `b` | Yes | Yes | Availability depends on PWM configuration |
| Status files under `/proc` | Yes | No | Kernel status snapshots and related data |
| `/tmp/NAME`, `/etc/NAME` | Yes | Yes | Regular RAM files |
| Directories | List | No | Enumerate with `getdents()`; cannot `read()` as a regular file |

See the [device guide](DEVICES.md) and [TTY guide](TTY.md) for data formats, `ioctl()` commands, and pin ownership rules. `/proc/devices` lists fixed registered devices and the `gpio/`, `adc/`, `pwm/`, and `i2c/` entry points, not every dynamically generated node.

## 3. GPIO and peripheral availability

In the default `kernel/pins.h`, GP0–17 and GP22–25 are configured as GPIO, GP18/19 as PWM, GP20/21 as UART1, and GP26/27 as I²C1 (SDA/SCL), and GP28 as ADC2. **On Pico W, GP23–25 have board-internal functions and should not be treated as external GPIO pins.** GP0–15 are reserved while the LED framebuffer is enabled. Node availability changes with pin and build configuration.

## 4. Limits of `/tmp` and `/etc`

| Item | Limit or behavior |
|---|---|
| Number of files | **11 total**, shared between `/tmp` and `/etc` |
| File size | **2048 bytes each** |
| Names | Direct children only; filename up to **27 bytes** (ASCII; the stored path includes a four-byte `tmp/` or `etc/` prefix) |
| Persistence | None; reset on reboot |
| Initial files | Pico: `/etc/rc`, `/tmp/test.s`, `/tmp/test.py`, `/tmp/wave.py` (4 files). Pico W: those files plus `/etc/index.html`, `/etc/fbcheck.html` and `/etc/pwm.html` (7 files) |
| Creation and deletion | Create with `O_CREAT`; delete with `unlink()`. Open files cannot be deleted |
| Writing | Partial writes at the capacity boundary; `OS_ENOSPC` when no space remains |

File metadata stays in kernel RAM; the eleven 2-KiB payloads are contiguous from `0x20032800`. See [Memory layout](MEMORY-LAYOUT.md).

`/etc/index.html` is served by the user-space `httpd`. It can be edited in RAM but changes are not saved to Flash. Nested subdirectories under `/tmp` and `/etc` cannot be created.

## 5. Paths and descriptors

Relative paths resolve against each task's current working directory. `.` and `..` are normalized, but arbitrary directory creation and symbolic links are not provided. Each task has 16 file descriptors; pipes and sockets also consume descriptors. See [Pipes](PIPE.md), [Socket programming](NETWORK-PROGRAMMING.md), and the [Specification](SPECIFICATION.md).

## 6. Implementation references

- `kernel/kernel.c`: `vdir_paths`, `dev_registry`, `vfs_registry`, `vdir_nth()`, `vfs_open()`, `tmp_*()`.
- `kernel/pins.h`: GPIO, ADC, PWM, UART, and I²C assignments.
- `include/piconix.h`: public API and error constants.
