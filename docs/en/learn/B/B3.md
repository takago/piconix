# B3　Flash, RAM, and tasks

*Part B — Intermediate: Observe UNIX*

**Learning objective:** Locate stored program images and running code.

So far `ps` has shown you tasks, but not **where their code and data are located**. The RP2040 has Flash and SRAM. PicoNIX executes kernel instructions directly from Flash through XIP, while a user program is copied into a fixed SRAM slot when launched. Distinguish the *stored image* from the *running image*.

**Terms:** XIP means executing instructions in place from Flash; PIC means position-independent code that can work at different load addresses; symbols help associate names with addresses. Beginners need not memorize address constants: start by recognizing that `0x100...` and `0x200...` refer to different regions. Keep the [memory-layout reference](../../reference/MEMORY-LAYOUT.md) open while exploring.

## B3.1 What stays in Flash?

PicoNIX runs kernel instructions from Flash with XIP. User application PIC images are stored in Flash, then copied into a selected **fixed RAM slot** when started. Distinguish *storage location* from *execution location*.

## B3.2 Inspect memory

### How to use and interpret `mem`

`mem` is a **read-only memory viewer**, not a memory editor. The full key reference is in the [mem usage guide](../../guides/MEM.md).

| Action | What it tells you |
|---|---|
| `mem -s` | List available symbol sources (**not** full-screen memory view) |
| `mem -s kernel` / `mem -s sh` | List symbols for the kernel or shell |
| `mem` | Show hexadecimal bytes at memory addresses |
| `1`–`6` inside `mem` | Jump to the six user RAM slots |
| `k` / `K` inside `mem` | Jump to kernel RAM / XIP Flash |
| `q` inside `mem` | Exit the viewer and return to the shell |

Seeing a symbol in `mem -s sh` does not imply that those bytes are visible in the current view. A symbol list and a hexadecimal memory dump are different representations. RAM may change during observation; a changed byte alone is insufficient to establish its cause.

```text
piconix# ps
piconix# mem -s
piconix# mem -s kernel
piconix# mem -s sh
```

Compare kernel and application symbols. Exact addresses and sizes vary by build. Do not modify memory while learning these concepts.

**Extra read-only observation:** Start `mem`; press `1`–`6` for user slots, `k` for kernel RAM, `K` for XIP Flash, and `q` to exit. Empty slots need not contain a program. Data can change while you are inspecting memory. Compare hexadecimal addresses with the [SRAM layout reference](../../reference/MEMORY-LAYOUT.md).

## B3.3 Why fixed slots?

RP2040 SRAM is limited. Fixed slots reduce implementation complexity, but impose limits on program size and concurrent tasks. PicoNIX does not implement Linux-style virtual memory.

## B3.4 Practice and check

**Guided experiment:** (1) Inspect tasks with `ps`; (2) list symbols with `mem -s`; (3) open `mem` and try keys `1`–`6`, `k`, and `K`; (4) exit with `q`; (5) compare addresses with the layout diagram. **Record separately:** region, slot/task label, and whether any displayed bytes changed. Do not assign a cause to a changing byte without more evidence.

Map `mem` observations onto the [memory-layout reference](../../reference/MEMORY-LAYOUT.md).

1. Are kernel and user instructions executed from the same location?
2. Why does PIC help with fixed RAM slots?
3. How do `ps` and `mem` differ?
