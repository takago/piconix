# B2　TTY and terminal I/O

*Part B — Intermediate: Observe UNIX*

**Learning objective:** Separate terminal input settings from screen rendering.

B1 established that a terminal can be accessed through an FD. But why might typed characters arrive only after Enter, or instead one at a time? TTY input settings account for this difference.

Keep **TTY input processing** (line editing, echo) separate from **application display control** (moving the cursor and redrawing a screen). Before changing modes, read the [TTY guide](../../guides/TTY.md) and the [terminal recovery guide](../../guides/TERMINAL.md): changing settings may make typing difficult.

## B2.1 Inspect the terminal

```text
piconix# tty
piconix# stty
```

A TTY abstracts character input/output. USB CDC, UART1, and Pico W Telnet have different transports but can use the same terminal behavior, depending on the board and configuration.

## B2.2 Line input vs character input

### Do not conflate three settings

| Setting | What it affects | Example |
|---|---|---|
| Canonical input | Whether input is collected by line | `stty icanon` / `stty -icanon` |
| Echo | Whether typed characters are displayed | `stty echo` / `stty -echo` |
| `O_NONBLOCK` | Whether `read()` waits for data | Controlled by `fcntl()` in a C program |

PicoNIX's `stty raw` is a **simplified shortcut** that disables canonical input and echo. It does not implement all POSIX raw-mode settings. If characters stop appearing after you change modes, do not assume the OS has failed. Follow the recovery procedure in the [TTY guide](../../guides/TTY.md).

Next you will inspect where programs and their state live in memory.

`stty` reports canonical input and echo settings. `stty raw` and `stty cooked` offer simplified toggles, **not** a complete POSIX raw-mode implementation. Begin by inspecting settings. Read the [TTY guide](../../guides/TTY.md) before changing them so you know how to restore your terminal.

**Optional exercise (only when you can restore your terminal):**

```text
piconix# stty
piconix# stty raw
piconix# stty
piconix# stty cooked
piconix# stty
```

`raw` is PicoNIX's simplified configuration for canonical input and echo, not a full POSIX `termios` raw mode. Read the [terminal recovery guide](../../guides/TERMINAL.md) first, and use `stty cooked` to restore normal interaction.

## B2.3 The kernel and the application

TTY input modes and newline conversion belong to terminal handling; full-screen drawing in `edit`, `vi`, and `mem` belongs to user programs. FD non-blocking behavior uses `fcntl()`, while TTY configuration uses `ioctl()`. These settings are not interchangeable.

## B2.4 Practice and check

**Safe starting point:** Record `tty` and `stty` without changing anything; identify settings such as `icanon` and `echo`. Only attempt a mode change once you know how to recover the terminal. **Key distinction:** TTY input processing and an application periodically redrawing a full-screen display (such as `mem`) are different responsibilities.

Record `tty` and `stty` output.

1. Are canonical input and echo the same setting?
2. Who handles terminal input, and who positions the cursor?
3. Why is `O_NONBLOCK` not equivalent to noncanonical mode?

Learning record: Write down **what you ran / what you observed / why it happened**.
