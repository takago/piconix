## A3.1 Available does not mean running

`ls /bin` lists **available commands**, whereas `ps` shows **currently running tasks**. A running instance has a PID; multiple instances of one program need not share a PID.

## A3.2 Run a background task

```text
piconix# ps
piconix# blink &
piconix# ps
piconix# cat /proc/tasks
```

`&` asks the shell to run a task in the background. Find its actual PID in `ps` and then use `kill PID`, replacing `PID` with the observed number. PicoNIX has a limited number of fixed process slots, so clean up background tasks.

## A3.3 Kernel resource management

The kernel assigns execution opportunities and RAM slots to tasks. The shell can accept commands while `blink` continues running because the CPU switches between activities.

**Caution:** `kill PID` is a placeholder: replace `PID` with a number found using `ps`. Compare `ps` and `cat /proc/tasks` to map program names and PIDs to live task state. Starting too many tasks exhausts fixed slots and prevents new tasks from starting.

## A3.4 Practice and check
