# A3　Programs and processes

*Part A — Beginner: Use UNIX*

**Learning objective:** Distinguish available programs from running processes.

A2 focused on the flow of bytes; now ask **when a program is actually running**. An image registered in `/bin` is not the same as a running process. `ps` is a snapshot of tasks at a particular moment.

**Terms:** A program is a collection of executable instructions; a process (called a task in parts of PicoNIX) is a running instance; a PID identifies that task. A RAM slot number is **not** a PID. Before starting a background job, review how to stop it using `help kill`.

## A3.1 Available does not mean running

`ls /bin` lists **available commands**, whereas `ps` shows **currently running tasks**. A running instance has a PID; multiple instances of one program need not share a PID.

## A3.2 Run a background task

### What does background execution demonstrate?

After starting `blink &`, the shell can accept further commands while `blink` remains active. This illustrates how the OS gives multiple tasks opportunities to run; it does not prove that the tasks execute simultaneously on the same core.

Record `ps` **before starting**, **while running**, and **after stopping** the task. Substitute the actual PID shown by `ps` in the `kill` command. Do not enter the literal placeholder `PID`. Confirm the process name and PID before terminating it, and do not leave background tasks consuming the limited task slots.

```text
piconix# ps
piconix# blink &
piconix# ps
piconix# cat /proc/tasks
```

`&` asks the shell to run a task in the background. Find its actual PID in `ps` and then use `kill PID`, replacing `PID` with the observed number. PicoNIX has a limited number of fixed process slots, so clean up background tasks.

## A3.3 Kernel resource management

The kernel assigns execution opportunities and RAM slots to tasks. The shell can accept commands while `blink` continues running because the CPU switches between activities.

**Caution:** `kill PID` is a placeholder: replace `PID` with a number found using `ps`. Compare `ps` and `cat /proc/tasks` to map program names and PIDs to live task state. Starting too many tasks exhausts fixed slots and prevents new tasks from starting.

## A3.4 Practice and check

**Guided experiment:** (1) Find `blink` in `/bin`; (2) run `ps`; (3) start `blink &`; (4) identify its PID; (5) stop that PID with `kill`. **Expected distinction:** The list of registered images stays the same while the list of running tasks changes. Being available to run is not the same as running.

Record what changes between successive `ps` outputs.

1. Are program names, PIDs, and task-slot numbers interchangeable?
2. How does using `&` change the interaction?
3. Which value identifies a task to `kill`?

Learning record: Write down **what you ran / what you observed / why it happened**.
