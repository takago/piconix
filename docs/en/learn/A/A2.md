# A2　Files and streams

*Part A — Beginner: Use UNIX*

**Learning objective:** Understand the difference between saved data and flowing data.

In A1 you explored names using `ls`. Now use those names to **store data** and to **pass data between programs**. This is a central UNIX idea: programs need not know each other's internals if their inputs and outputs can be connected.

The shell interprets the new symbols. `>` redirects output to a file, `>>` appends to that file, and `|` sends output to another command. The `echo` and `cat` programs do not parse these shell operators themselves. Refer to the [pipe and standard I/O guide](../../guides/PIPE.md) for limits and the underlying FD operations.

## A2.1 Create and read a file

On PicoNIX, run:

```text
piconix# echo hello > /tmp/hello.txt
piconix# cat /tmp/hello.txt
piconix# cp /tmp/hello.txt /tmp/copy.txt
piconix# cat /tmp/copy.txt
```

`echo` outputs text, `>` redirects that output into a file, `cat` reads it, and `cp` creates a copy. PicoNIX stores `/tmp` in RAM, so its contents disappear after a reboot.

`cp SRC DST` copies RAM files directly under `/tmp` or `/etc`. It overwrites an existing destination; copies disappear on reboot. A failed write can leave an incomplete destination.

```text
piconix# cat -n /tmp/hello.txt
piconix# echo >> /tmp/hello.txt
piconix# cat -n /tmp/hello.txt
```

`cat -n` numbers **blank lines too** for display without modifying the stored file; `>>` appends data.

## A2.2 Standard input and output

### Draw the two data paths

```text
echo hello  >  /tmp/hello.txt      text → RAM file
echo hello  |  cat                 text → pipe → cat → terminal
```

A file created with `>` remains after the command exits (until reboot). A pipe transfers bytes to a reader; it does **not** automatically save anything in `/tmp`. **Standard input** is a program's default input channel, and **standard output** is its normal output channel. Part B explains these through file descriptors.

**Predict before running:** `echo hello | grep zzz` normally prints no line because `grep` selects lines containing the requested string. Compare it with `grep hello`. PicoNIX's `grep` performs a simple string search rather than full regular-expression matching.

With a path argument, `cat` reads that file. Without one, it reads **standard input**. A program can write to **standard output** without knowing whether it is a terminal or a pipe.

```text
piconix# echo hello
piconix# echo hello | cat
piconix# echo hello | cat -n
```

## A2.3 Connect programs with a pipe

```text
piconix# echo hello | grep hello | cat
```

`|` connects one program’s standard output to another’s standard input. This is **not** the same as writing a temporary file. PicoNIX supports pipelines of up to three commands; it does not implement all the parsing and redirection features of a full Linux shell.

Try `echo hello | cat -n` and `echo hello | grep hello | cat`. Distinguish standard input (FD 0), standard output (FD 1), and standard error (FD 2). A pipe passes a temporary byte stream, not a saved RAM file. Short-lived programs may have already exited by the time you run `lsof`.

## A2.4 Practice and check

**Guided experiment:** (1) Save data using `echo abc > /tmp/a.txt`; (2) read it with `cat /tmp/a.txt`; (3) run `echo abc | cat`; (4) check `ls /tmp`. **Expected distinction:** Both commands can display `abc`, but only the first creates a persistent (until reboot) RAM file. The second uses a temporary pipe.

Compare `echo hello > /tmp/hello.txt` with `echo hello | cat`.

1. Which result can you inspect later with `cat /tmp/hello.txt`?
2. Who selects the input source for `cat`?
3. What changes when you replace `cat` with `grep hello`?

Learning record: Write down **what you ran / what you observed / why it happened**.
