# A4　Beginner capstone: a small UNIX experiment

*Part A — Beginner: Use UNIX*

**Learning objective:** Bring the shell, files, streams, and processes together.

This chapter is not a test of whether you memorized each command. It asks you to **form a goal, choose operations, observe the result, and explain it**. Bring together the namespace of A1, streams of A2, and running tasks of A3.

Consider a simple goal: save a string, verify its contents, then pass it to another command. Before typing, identify which of `echo`, `cat`, `|`, and `ps` helps store or transfer bytes and which one reports execution state.

## A4.1 Design a simple observation

Repeat these four steps yourself: (1) locate a program in `/bin`, (2) create a RAM file with `echo`, (3) connect commands with `|`, and (4) inspect running tasks using `ps`. Label each step as a file, stream, or process operation.

## A4.2 Record results

### Keep a short experiment log

| Field | Example |
|---|---|
| Goal | Save `hello` and read it back |
| Prediction | A file created under `/tmp` remains after `echo` exits |
| Action | `echo hello > /tmp/hello.txt`, then `cat /tmp/hello.txt` |
| Observation | The displayed text and file path |
| Explanation | The shell redirected standard output into a file |

**Bridge to Part B:** You can now use `cat` with a terminal or a file, but you have not yet explained *how* the OS connects the same program to different I/O targets. Part B introduces file descriptors and the VFS to answer that question.

```text
piconix# echo lesson > /tmp/lesson.txt
piconix# cat /tmp/lesson.txt
piconix# echo lesson | cat -n
piconix# ps
```

Record **command → observation → explanation**, rather than copying the screen alone. PIDs and other runtime details are not constant.

## A4.3 Three UNIX viewpoints

You can now (1) locate resources by name, (2) connect input/output, and (3) observe execution units. Part B explains these familiar actions using FDs, TTYs, memory, and system calls.

## A4.4 Check your progress

**Build your experiment:** Predict that a file created with `>` can be read after `echo` exits. Save a string, use `cat` to verify, and then try a pipe. Draw two routes that produce similar screen output. If results differ from your expectation, check the command host, spelling, and path rather than inventing an explanation.

1. Explain the difference between `>` and `|`.
2. Explain why `/tmp` and `/proc` are different.
3. Find and safely terminate a running background task.

Move on to Part B when you can explain all three.

Learning record: Write down **what you ran / what you observed / why it happened**.
