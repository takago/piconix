# A1　Entering PicoNIX and UNIX

*Part A — Beginner: Use UNIX*

**Learning objective:** Start the shell and distinguish commands from operating-system responsibilities.

**Before you begin:** All you need is a terminal connected to a running PicoNIX system. You do not need to know C or electronics yet. If the device is not ready, start with the [setup guide](../../setup/SETUP.md).

You do not have to memorize kernel internals to learn UNIX. Keep three roles distinct: **you type a command**, **the shell interprets it**, and **the OS runs programs and manages resources**. For example, typing `ls /tmp` is an interaction with the shell, while obtaining the directory entries involves OS functionality. You will revisit that distinction throughout the course.

## A1.1 What does it mean to use UNIX?

The **shell** accepts commands, programs perform work, and the **kernel** manages execution and I/O resources. Keep these three roles distinct. PicoNIX is a small UNIX-like operating system designed to make these roles observable on hardware.

## A1.2 Connect to the console

### Reading the screen

- `piconix#` is the PicoNIX prompt, not part of what you type. Do not confuse the PicoNIX shell with the **Linux host** terminal used to connect to it.
- `pwd` reports the current working directory; `ls /tmp` lists entries at a specified path. They answer different questions.
- Names under `/bin` identify available programs; `/proc` presents live OS state. The fact that both can be listed with `ls` does not mean they are ordinary disk files.

**Quick check:** Run `help cat`, then `cat /proc/uptime`. The first explains a command; the second reads a piece of current system state. If an example fails, check the command syntax with `help` before assuming that the OS is broken.

Follow [Setup](../../setup/SETUP.md) to flash a Pico or Pico W and open the USB terminal. `piconix#` represents the prompt and is not part of what you type. Run these commands **inside PicoNIX**:

```text
piconix# help
piconix# pwd
piconix# ls /
```

Use `help` to discover commands, `pwd` to display the current directory, and `ls` to list directory entries.

## A1.3 Explore the namespace

```text
piconix# ls /bin
piconix# ls /tmp
piconix# ls /dev
piconix# ls /proc
```

`/bin` presents registered programs, `/tmp` contains writable RAM files, `/dev` exposes devices, and `/proc` presents live system state. A file-like name does **not** mean that everything is stored in the same way.

**Extra observation:** Compare `pwd` with `ls /`. `pwd` reports the current directory, while `ls` lists entries at the specified path. Both `ls /dev` and `ls /proc` return names, but the former presents device entry points and the latter current OS state. PicoNIX does not necessarily support every command from desktop Linux. Check `help` or `help COMMAND` for supported syntax.

## A1.4 Practice and check

**Guided experiment:** (1) Run `help`; (2) record `pwd`; (3) compare `ls /bin` with `ls /proc`; (4) explain why the same `ls` command lists different kinds of resources. Focus on *where the names come from*. If something fails, verify that you are at the PicoNIX prompt and consult `help ls`.

Use `help cat`, then find `cat` in `ls /bin`. Explain:

1. What do the shell and kernel do differently?
2. How does `/bin` differ from `/proc`?
3. How do you distinguish a PicoNIX shell from a Linux host terminal?

Learning record: Write down **what you ran / what you observed / why it happened**.
