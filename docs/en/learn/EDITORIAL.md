# Textbook editorial policy

- **Storyline:** Part A uses the OS, Part B observes mechanisms, Part C reads and modifies source. Every chapter provides context, explanation, a lab, and checks so it can be studied on its own.
- **Numbering:** `A1` is a chapter; `A1.1` is a section. The A/B/C numbering is **reserved for textbook lessons**. Numbers in technical references are local headings, not textbook IDs.
- **Navigation:** Only numbered chapters have Previous / Part contents / Next. Optional Pico W chapters branch away from the main path.
- **Links:** Identify supplementary guides, technical references, and development guides explicitly. Return to the last textbook chapter to resume.
- **Lab safety:** `piconix#` denotes PicoNIX; `sh` blocks denote the Linux host. Mark optional hardware and network security conditions.
- **Technical evidence:** Review command and API descriptions against the latest supplied source, and label untested extension examples. Keep Japanese/English chapter structures and safety notes aligned.
- **Single source of truth:** The numbered textbook owns the learning sequence and foundational labs. Usage guides own command-specific details; references own APIs, limits, and contracts; development guides own implementation workflows; source code determines actual behavior.
- **Retire duplicates:** Once a basic lab has been integrated into the textbook, remove its old separate page rather than maintaining competing copies. Consult Git history for obsolete learning paths.
- **Maintenance:** Check Markdown links and Japanese/English parity after every update. History is not a current specification.
