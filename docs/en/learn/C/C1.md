## C1.1 Read an application

On the Linux host, inspect `userland/apps/hello.c` and `userland/lib/crt0.c`. A PicoNIX program starts in `main()` and uses a small system-call wrapper layer, not the host’s libc or Pico SDK directly.

## C1.2 Write a small command

For example, create `userland/apps/greet.c` **on the host**:

```c
#include "stdio.h"

int main(int argc, char *argv[]) {
    const char *name = (argc > 1) ? argv[1] : "PicoNIX";
    printf("Hello, %s!\n", name);
    return 0;
}
```

Register the application in `CMakeLists.txt` and `kernel/main.c`. Consult the [programming guide](../../development/apps/c/PROGRAMMING.md) to check the exact registration steps and unused program IDs.

## C1.3 Build and flash

On the Linux host, use `./tools/build_sdk.sh -DPICO_BOARD=pico -DCMAKE_BUILD_TYPE=MinSizeRel`, or select `pico_w`. Set the required SDK/toolchain paths following [Setup](../../setup/SETUP.md). Building a UF2 file does not change the running device until you flash it.

## C1.4 Practice and check

Reading the existing `hello` implementation is enough for the basic exercise. For an extension, run `greet Alice` after flashing.

1. What happens when `main()` returns?
2. Does `printf()` directly operate the USB controller?
3. When does registration happen, and when is a RAM slot loaded?

Learning record: Write down **what you ran / what you observed / why it happened**.
