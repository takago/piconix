# C1　Start with a user program

*Part C — Advanced: Read and extend UNIX*

**Learning objective:** Begin with a small C application before changing kernel code.

Part B observed the boundary between applications and the OS. Part C begins with **user programs**, where changes tend to have a smaller impact than kernel edits. This lets you practice building, running, observing, and reviewing changes before touching the kernel.

`userland/apps/` contains individual commands; `userland/lib/` contains shared functions and system-call wrappers. Reading an application is not the same task as reading its supporting library. Use the [C application development guide](../../development/apps/c/PROGRAMMING.md) as the authoritative procedure for registration and builds.

## C1.1 Read an application

On the Linux host, inspect `userland/apps/hello.c` and `userland/lib/crt0.c`. A PicoNIX program starts in `main()` and uses a small system-call wrapper layer, not the host’s libc or Pico SDK directly.

## C1.2 Write a small command

### Follow the existing `hello` first

On the Linux host, read (1) `userland/apps/hello.c`, (2) `userland/lib/crt0.c`, and then (3) relevant parts of `userland/lib/syscalls.c`.

| Location | Why read it |
|---|---|
| `hello.c` | User-visible behavior and `main()` |
| `crt0.c` | Startup and entry into `main()` |
| `syscalls.c` | Where `write()` and related calls cross into the kernel |

Registering a new command involves keeping its **program name, ID, and build configuration** consistent. Copying the short example alone does not automatically register it. Check the current [development instructions](../../development/apps/c/PROGRAMMING.md) and work in a separate branch rather than overwriting an existing application.

For example, create `userland/apps/greet.c` **on the host**:

```c
#include "stdio.h"

int main(int argc, char *argv[]) {
    const char *name = (argc > 1) ? argv[1] : "PicoNIX";
    printf("Hello, %s!\n", name);
    return 0;
}
```

Register the application in `CMakeLists.txt` and `kernel/main.c`. Consult the [programming guide](../../development/apps/c/PROGRAMMING.md) to check the exact registration steps and unused program IDs.

## C1.3 Build and flash

On the Linux host, use `./tools/build_sdk.sh -DPICO_BOARD=pico -DCMAKE_BUILD_TYPE=MinSizeRel`, or select `pico_w`. Set the required SDK/toolchain paths following [Setup](../../setup/SETUP.md). Building a UF2 file does not change the running device until you flash it.

## C1.4 Practice and check

**Source exercise:** Find where `hello.c` determines the text to print. Locate the startup path in `crt0.c` and the kernel request in `syscalls.c`. **Deliverable:** A 3–5 step diagram from `main()` to standard output, with source filenames. Attempt a new application only after the existing path is clear.

Reading the existing `hello` implementation is enough for the basic exercise. For an extension, run `greet Alice` after flashing.

1. What happens when `main()` returns?
2. Does `printf()` directly operate the USB controller?
3. When does registration happen, and when is a RAM slot loaded?

Learning record: Write down **what you ran / what you observed / why it happened**.
