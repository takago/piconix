# C3　Follow SVC, FDs, and VFS in source

*Part C — Advanced: Read and extend UNIX*

**Learning objective:** Trace a write from user code to its output destination.

B4 used `trace run hello` to observe calls such as `write()`. Now trace a **source-code path** explaining how that call reaches terminal output. Distinguish a regular C function call from the SVC exception that crosses the user/kernel boundary.

First check the arguments and return value of `write` in the [system-call reference](../../reference/SYSCALLS.md); the [trace guide](../../guides/TRACE.md) explains how to observe it again. Review B1 and the [filesystem reference](../../reference/FILESYSTEM.md) for the meaning of FD and VFS.

## C3.1 From user code to SVC

Follow `userland/apps/hello.c` → `write()` and `call()` in `userland/lib/syscalls.c` → `include/piconix_syscall.h` → the SVC handler in `kernel/context.S` → `os_svc_dispatch()` in `kernel/kernel.c`. Distinguish the public C API from the ABI.

## C3.2 From syscall to I/O object

### Follow one `write` call

```text
hello.c requests output
  → userland/lib/syscalls.c
  → SVC (system-call boundary)
  → dispatcher in kernel/kernel.c
  → write operation for the FD's target
  → return value to the caller
```

This is a **reading route**, not a complete call graph. Check each arrow in the source. A successful `write()` generally returns a byte count; do not assume that the result always equals the requested length. Errors and partial writes matter.

For `echo hello | cat`, the shell creates a pipe and passes FDs to child processes. A reader sees EOF only once **every writer FD has closed and no data remains**. The [pipe guide](../../guides/PIPE.md) gives the details.

Locate the `SYS_WRITE` case and follow FD lookup and VFS dispatch. The entry is similar whether the FD points to a terminal, a RAM file, or a pipe; the final handler differs.

## C3.3 Pipes and waiting

Read pipeline setup in `userland/apps/shell.c`, then track `pipe()`, `dup2()`, `close()`, and EOF. For a first example, follow `echo hello | cat` rather than every error-handling branch.

## C3.4 Reading assignment

**Source exercise:** Select one `write` event from B4. Find `SYS_WRITE`, the SVC entry, `os_svc_dispatch()`, and the FD-dependent write path. **Deliverable:** The file and function name at each step. Begin with one standard-output write; ordinary files, TTYs, and pipes take different paths.

Run `trace run hello` again and relate the output to the code.

1. Where are syscall numbers defined?
2. Which layer selects the I/O destination?
3. Under what conditions does a pipe reach EOF?

Learning record: Write down **what you ran / what you observed / why it happened**.
