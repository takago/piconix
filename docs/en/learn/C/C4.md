## C4.1 Begin with VFS

Find path dispatch and FD management in `kernel/kernel.c`; then inspect `kernel/gpio.c`, `kernel/fb.c`, `kernel/adc.c`, and `kernel/pwm.c`. Note which jobs belong to the VFS and which are hardware-specific.

## C4.2 Read/write and ioctl

Device operations can share file APIs, but configuration often needs `ioctl()`. `/proc` exposes state rather than persistent storage. Keep **device drivers and networking as separate learning steps**.

## C4.3 Check before editing

Review the [driver development guide](../../development/drivers/DRIVER-DEVELOPMENT.md): path and ID conflicts, reserved pins, FD cleanup, and error returns. **Source reading is required; wiring or edits are optional**.

## C4.4 Reading assignment

Draw path → FD → VFS → device handler for one device.

1. Why might a device need `ioctl()`?
2. How does a device node differ from a regular file?
3. Which safety checks matter before hardware changes?

Learning record: Write down **what you ran / what you observed / why it happened**.
