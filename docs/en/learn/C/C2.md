# C2　Boot, tasks, and scheduling

*Part C — Advanced: Read and extend UNIX*

**Learning objective:** Trace the kernel path that starts the first user shell.

Writing a user program is not enough to explain how the very first shell starts. Here you separate **boot initialization**, **image registration**, **task creation**, and **context switching**. Open the boot and scheduling sections of the [kernel reading guide](../../development/kernel/KERNEL-READING-GUIDE.md) before starting.

Read from caller to callee. Start at `main()` in `kernel/main.c`, and distinguish `register_image()` (recording an available image) from `os_start_program()` (starting execution). Do not attempt to read every kernel file from its first line.

## C2.1 From main to sh

Read `kernel/main.c` and follow `os_init()` → `register_image()` → `net_init()` → `os_init_idle()` → `os_start_program(2)` → `os_start()`. Draw how **registration** differs from **starting** a task.

## C2.2 Prepare and switch tasks

### Record a small source map

```text
initialization → image registration → first task setup → scheduler starts
                                  ↓
                           RAM slot / initial stack
```

This is a **conceptual map**; verify actual function names and branches using the [kernel reading guide](../../development/kernel/KERNEL-READING-GUIDE.md) and source code.

**Keep the roles distinct:** SysTick provides a periodic interrupt; the scheduler selects a task; PendSV is used for context switching. Calling all three simply “task switching” hides the differences. Connect this source inspection to your `ps` observations and to the memory-slot view from B3.

Find `spawn_in_slot()`, `os_start_program()`, and `os_schedule()` in `kernel/kernel.c`, then follow SysTick and PendSV in `kernel/context.S`. Separate task selection from CPU context switching.

## C2.3 RAM slots and registers

Relate the fixed RAM slot, initial stack, saved registers, and PSP. Check constants in `include/piconix.h` and functions in the [function index](../../../FUNCTIONS.md), rather than memorizing addresses. PicoNIX does not duplicate Linux’s virtual memory model.

## C2.4 Reading assignment

**Source exercise:** Number the initialization and registration calls in `kernel/main.c`. Then find the task-selection path in `kernel/kernel.c` and context save/restore code in `kernel/context.S`. **Deliverable:** An annotated diagram from registered image to RAM slot, running task, and context switch.

Draw a 5–10 function flow diagram from boot to the first `sh`.

1. What differs between image registration and task launch?
2. How do SysTick and PendSV divide their work?
3. Why does the idle task exist?

Learning record: Write down **what you ran / what you observed / why it happened**.
