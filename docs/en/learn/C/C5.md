## C5.2 Two network layers

### Explain HTTP versus Telnet in code

| Aspect | HTTP | Telnet |
|---|---|---|
| Implementation | `userland/apps/httpd.c` | `kernel/net_service_telnet.c` |
| Execution | User process | Kernel-resident service |
| What to inspect | Startup, shutdown, socket FD | Connection handling inside the kernel |

Both use TCP, but live in different layers. The UDP 2000 remote-device service is another kernel service. For user-facing socket calls, read the [network programming guide](../../development/apps/c/NETWORK-PROGRAMMING.md); for configuration and connectivity, use the [network reference](../../reference/network/NETWORK.md).

Read `kernel/net.c` for Wi-Fi/lwIP initialization and management, then `kernel/net_socket.c` for user-process sockets. In `userland/apps/httpd.c`, trace `socket()`, `bind()`, and `listen()` through the syscall boundary.

## C5.3 Kernel vs user-space services

The Telnet TCP 23 and remote-device UDP 2000 services are kernel-resident; HTTP TCP 80 runs in the user-space `httpd`. Compare memory, process lifetime, restart, and FD handling. Keep unauthenticated and plaintext services on an isolated lab network.

## C5.4 Reading assignment

**Source exercise:** Start from `httpd` opening a socket and draw the path through the user API, kernel socket code, and lwIP. Compare this with where the kernel Telnet service accepts connections. **Comparison:** Who controls stopping or restarting HTTP versus Telnet?

1. How do `kernel/net.c` and `kernel/net_socket.c` differ?
2. How is `httpd` unlike the kernel Telnet server?
3. Why does the idle task help service networking?
